# CDP 动态调试立创EDA — 经验记录

> 目标场景：新版加密 .eprj2 的内容导出（静态解析不可行，见 TODO.md）。
> 全部脚本在 `probes/`：`cdp_eval.py`（最小客户端）、`export_newfmt.py`
> （成品导出）、`dbg_*.py`（过程探针）。

## 一、启动与连接

```bat
rem CDP（渲染层）：
lceda-pro.exe --remote-debugging-port=9222 "C:\...\工程.eprj2"
rem 主进程 Node（可 require 任意模块）：
lceda-pro.exe --inspect=9229 ...
rem 启动即暂停（预 hook 用，注意 brk 暂停点 require 不可用）：
lceda-pro.exe --inspect-brk=9229 ...
```

- `http://127.0.0.1:9222/json/list` 枚举 targets（page/worker）
- Python 无第三方依赖时用 `probes/cdp_eval.py` 的手写 WebSocket 客户端
  （握手+帧编解码 ~80 行）；`Runtime.evaluate` + `returnByValue` 即可
  执行任意 JS 拿结果。

## 二、渲染层关键入口点（实测地图）

| 入口 | 内容 |
| --- | --- |
| `SCH.gVars.currentProject` | 工程元信息（projectId/isV2Format/branchUuid） |
| `SCH.gVars.projectMgr.sheetCache.sheet` | **全部页元数据** {uuid: {title, schematic_uuid, docType...}} |
| `SCH.gVars.projectMgr.componentCache.symbol/.device` | 符号/器件缓存（symbol 值含 docType=17 可判 CBB） |
| `SCH.gVars.projectMgr.instanceAttrMgr.savedData` | CBB 成员母图位号映射（仅记录改名成员） |

## 三、踩坑记录

1. **worker 不可直连 CDP**：/json/list 里的 worker target 直连 evaluate
   超时。解法：连 browser 端点（/json/version 的 webSocketDebuggerUrl）→
   `Target.setAutoAttach{flatten:true}` → 逐 worker
   `Target.attachToTarget` → 带 sessionId 发 evaluate。
   但本项目 4 个 worker 仍不回 evaluate（消息循环被业务占满）——
   worker 内逻辑只能静态分析（project-worker.js）。
2. **ticket 每段独立计数**：epru 增量日志的 ticket 不能全局比较，
   合并须用 (段序, ticket) 双键（Epro2DB._iter_doc_lines）。
3. **--inspect-brk 暂停点 `require` 不可用**：用
   `process.mainModule.require('crypto')`。
4. **渲染层 hook WebCrypto 零捕获**：history_data 的解密不经渲染层
   WebCrypto；dispose+重载 getSourceCode 依旧明文——数据来自主进程内存
   缓存（工程打开时已解密）。
5. **getSourceCode 是重编码非解密**：从内存活对象
   （shapeManager/idManager → uploadTo 编码器）重新生成文本——
   内存活文档才是真相源。
6. **addScriptToEvaluateOnNewDocument + Page.reload** 可在页面加载前
   注入 hook（用于捕获打开时刻的调用）；但解密不在渲染层，捕获为零。

## 四、解密结论（2026-08-21）

- `history_data.dataStr`（base64 blob，熵 8.00）的解密发生在
  **pro-mgr worker 内部**（CDP 不可达），或主进程原生层；本地 bundle
  无应用级解密代码（主进程仅通用 ORM；渲染层仅 crypto-browserify 库内部）。
- 静态逆向二进制容器格式：已定位解析器在 project-worker.js
  （onLine 12 参数版 = 二进制路径），格式规范未完全提取，需多轮工作。
- **标准工作流（推荐）**：全离线打开 .eprj2 → 运行
  `probes/export_newfmt.py` → 得 `<名>_export.epro2` → 工具全功能分析。
  导出内容：73 页+224 符号 getSourceCode 明文 + DEVICE deviceResult +
  structure 层级合成 + INSTANCE 位号映射，实测全功能可用。

## 五、export_newfmt.py 使用

```bat
rem 1) 启动（全离线即可）：
lceda-pro.exe --remote-debugging-port=9222 "C:\...\工程.eprj2"
rem 2) 导出：
python probes\export_newfmt.py "C:\...\工程.eprj2"
rem 3) 分析导出包：
python lceda_reader.py --eprj "C:\...\工程_export.epro2" tree/netlist/...
```

注意：sheetCache 可能含已删页残留——导出以 structure.sheets 为权威清单
过滤；componentCache 未覆盖的符号（未打开过的库元件）会缺失（实测
224/226 覆盖）。
