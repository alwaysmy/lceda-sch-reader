# CDP 动态调试立创EDA — 经验记录

> 目标场景：新版加密 .eprj2 的内容导出（静态解析不可行，见 TODO.md）。
> 全部脚本在 `probes/`：`cdp_eval.py`（最小客户端）、`export_newfmt.py`
> （成品导出）、`dbg_*.py`（过程探针）。

## 一、启动与连接

```bat
rem CDP（渲染层）：
lceda-pro.exe --remote-debugging-port=9222 "C:\...\工程.eprj2"
rem 主进程 Node（可 require 任意模块）：
lceda-pro.exe --inspect=9229 ...
rem 启动即暂停（预 hook 用，注意 brk 暂停点 require 不可用）：
lceda-pro.exe --inspect-brk=9229 ...
```

- `http://127.0.0.1:9222/json/list` 枚举 targets（page/worker）
- Python 无第三方依赖时用 `probes/cdp_eval.py` 的手写 WebSocket 客户端
  （握手+帧编解码 ~80 行）；`Runtime.evaluate` + `returnByValue` 即可
  执行任意 JS 拿结果。

| 入口 | 内容 |

## 三、踩坑记录

1. **worker 不可直连 CDP**：/json/list 里的 worker target 直连 evaluate
   超时。解法：连 browser 端点（/json/version 的 webSocketDebuggerUrl）→
   `Target.setAutoAttach{flatten:true}` → 逐 worker
   `Target.attachToTarget` → 带 sessionId 发 evaluate。
   但本项目 4 个 worker 仍不回 evaluate（消息循环被业务占满）——
   worker 内逻辑只能静态分析（project-worker.js）。
2. **ticket 每段独立计数**：epru 增量日志的 ticket 不能全局比较，
   合并须用 (段序, ticket) 双键（Epro2DB._iter_doc_lines）。
3. **--inspect-brk 暂停点 `require` 不可用**：用
   `process.mainModule.require('crypto')`。
4. **渲染层 hook WebCrypto 零捕获**：history_data 的解密不经渲染层
   WebCrypto；dispose+重载 getSourceCode 依旧明文——数据来自主进程内存
   缓存（工程打开时已解密）。
5. **getSourceCode 是重编码非解密**：从内存活对象
   （shapeManager/idManager → uploadTo 编码器）重新生成文本——
   内存活文档才是真相源。
6. **addScriptToEvaluateOnNewDocument + Page.reload** 可在页面加载前
   注入 hook（用于捕获打开时刻的调用）；但解密不在渲染层，捕获为零。

## 四、解密结论（2026-08-21）

- `history_data.dataStr`（base64 blob，熵 8.00）的解密发生在
  **pro-mgr worker 内部**（CDP 不可达），或主进程原生层；本地 bundle
  无应用级解密代码（主进程仅通用 ORM；渲染层仅 crypto-browserify 库内部）。
- 静态逆向二进制容器格式：已定位解析器在 project-worker.js
  （onLine 12 参数版 = 二进制路径），格式规范未完全提取，需多轮工作。
- **标准工作流（推荐）**：全离线打开 .eprj2 → 运行
  `probes/export_newfmt.py` → 得 `<名>_export.epro2` → 工具全功能分析。
  导出内容：73 页+224 符号 getSourceCode 明文 + DEVICE deviceResult +
  structure 层级合成 + INSTANCE 位号映射，实测全功能可用。

## 五、export_newfmt.py 使用

```bat
rem 1) 启动（全离线即可）：
lceda-pro.exe --remote-debugging-port=9222 "C:\...\工程.eprj2"
rem 2) 导出：
python probes\export_newfmt.py "C:\...\工程.eprj2"
rem 3) 分析导出包：
python lceda_reader.py --eprj "C:\...\工程_export.epro2" tree/netlist/...
```

注意：sheetCache 可能含已删页残留——导出以 structure.sheets 为权威清单
过滤；componentCache 未覆盖的符号（未打开过的库元件）会缺失（实测
224/226 覆盖）。

## 六、官方扩展 API（_EXTAPI_ROOT_）与 MCP（2026-09-03 实测）

客户端内置完整官方扩展 API（对应 `assets/pro-api/*/api-types.d.ts`，
21491 行类型声明）：

- **入口**：渲染层 window 全局 `_EXTAPI_ROOT_`（extensionUuid="eda"），
  命名空间：`dmt_*`（Board/EditorControl/Project/Schematic）、
  `lib_*`（Device/Symbol/Footprint/**Cbb**/LibrariesList）、
  `sch_*`（Document/Drc/Net/Netlist/Primitive*/SimulationEngine/Utils）、
  `pcb_*`、`pnl_*`、`sys_*`（Dialog/Message/ShortcutKey/Unit/...）。
  底层传输 = `_MSG_BUS2_EXTAPI_` 上的 `extensionApi.*` 主题 RPC，
  因此**全部 API 可直接从 CDP 以 Promise 方式调用**，无需装扩展。
- **官方 MCP 现状**：easyeda 官方组织仅有
  `github.com/easyeda/extension-dev-mcp-tools`（面向扩展开发调试：
  自动导插件+采集控制台日志）；操作原理图/PCB 的 MCP 均为社区项目
  （hyl64/jlcmcp、sengbin/JLCEDA-MCP），底层即上述官方 API。
  本工具直接走 `_EXTAPI_ROOT_`，等价且少一层。
- **实测可用操作**（均为 await Promise）：
  - `sch_PrimitiveBus.create('D[0:7]', [x1,y1,x2,y2])` 建总线
  - `sch_PrimitiveWire.create([x1,y1,...])` 建导线（支持多段 L 形）
  - `sch_PrimitiveComponent.create({libraryUuid, uuid}, x, y)` 放器件
    （`lib_Device.search('10k')` 先搜 uuid；注意 API 放置**无 Designator**
    属性，需 UI 重编号）
  - `createNetFlag('Ground','GND',x,y)` 会弹对话框阻塞——CDP 下慎用
  - `sch_Document.save()` / `navigateToCoordinates(x,y)`（后者实测
    不动视图，视图控制用 `doc.canvas.scene.zoom.scrollXYIntoViewCenter(
    内部x, 内部y)`，内部坐标 Y 取负）
  - `sys_ShortcutKey.getShortcutKeys()` 等查询类均可用
- **画布坐标→屏幕像素**：`scene.viewBox`（可见文档区域，内部坐标）+
  `scene.viewPort`（屏幕 css px 区域）线性映射即可驱动
  `Input.dispatchMouseEvent` 真实鼠标事件（画线/菜单等 UI 操作），
  校验点：netlabel 等已知坐标元素应映射到预期像素。

## 七、调试操作经验与坑（2026-09-02/03 汇总）

**操作流程**（`probes/cdp_probe.py` = eval harness，结果可存文件）：

1. 带 `--remote-debugging-port=9222` 重启客户端（运行中实例无法补挂）；
   `/json/list` 多窗口时按 title 挑目标（每工程一个 page target）。
2. 先装 hook 再触发动作：包 `SCH.gVars.messageBus.publish`、
   `messageBus.rpcCall`（含 `p.then()` 记响应）、`window.fetch`、
   `XMLHttpRequest.open/send`、`window.Worker`、`Storage.prototype.setItem`。
3. 驱动方式优先级：**直接 rpcCall > 官方 API（_EXTAPI_ROOT_）>
   SCH.doCommand(cmd) > DOM 按钮点击 > Input 鼠标事件**。能拿参数形状
   （hook 先行 + 看 worker 端 handler）就不驱动 UI。

**坑清单**：

1. `addScriptToEvaluateOnNewDocument` 在 document-start 执行时 `SCH`
   未定义，hook 必须内部轮询等 `SCH.gVars.messageBus` 就绪；实测该注入
   曾整体不生效，手动重装 hook 更可靠。
2. doCommand 派发器源码是压缩 switch：提取 case 用正则
   `/case\s*["']?([A-Za-z0-9_:\.\-]+)/`（`case"xxx"` 无空格，
   `\s+` 会 0 命中）；共 173 case（清单 probes/tmp/docommand_all.json）。
3. React 输入框赋值必须 `Object.getOwnPropertyDescriptor(
   HTMLInputElement.prototype,'value').set.call(el, v)` + 派发
   `input`/`change` 事件，直接 el.value 无效。
4. 对话框按钮点击前要 `offsetParent!==null` 过滤可见性；同一对话框
   DOM 有多层重复（lc_modal_dialog_box/zvEgQ/body），取最外层找按钮。
5. `docMemoryManager.docMap` 在部分窗口/时机为空，取当前文档用
   `docMemoryManager.getActiveDoc()`；文档 `consistencyImpl.getSourceCode()`
   在页签从未激活（sourceCodeIdMap 空）时会抛 undefined 错误。
6. 活模型形状树在 `shapeManager._root`（递归 children），rTree 命中的
   是渲染对象（cmdKey 全 "Object"）；形状 id 与文件记录 id 不保证一致
   （引擎会重建并换 id）。
7. **上传只走用户动作事务**：官方 API/引擎内部新建的模型（如
   netPolymerization 自动生成的 BusEntry）不触发上传；要落盘需再做一个
   UI 动作（如画一根线）后 `doCommand('file_save')`。API 的
   `sch_Document.save()` 只标记保存，不重编码全部活模型。
8. `navigateToCoordinates` 实测不改变视图（原因未深究）；改用
   `scene.zoom.scrollXYIntoViewCenter(内部x, 内部y)`（Y 取负）。
9. 半离线模式下 `file_save` 后磁盘 .eprj2 的 documents 主表仍为空
   （新版加密格式，内容在 project_structures + history_data，见
   docs/CDP运行时操作探测-2026-09-02.md §6）。
10. client 设置对话框（运行模式等）走 Electron IPC（windowBridge.bus），
    hook messageBus 抓不到；工程级配置才走 `/PrjDB/config/*`。
11. 新建工程会自动创建 Board1/Schematic1(页P1)/PCB1/Panel1 与 CONFIG
    文档（default_sheet 指向图框器件 uuid）——探测时页对象比预期多。
