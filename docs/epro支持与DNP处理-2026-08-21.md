## 四、DNP（不上BOM/不上PCB）链路语义

### 标志来源（实例级 ATTR，两案例实测）

- `Add into BOM = yes/no`（E1 238 处、E2 7 处；E1 有 **76 个不上BOM 的 R**，
  含多个 DNP 0Ω）
- `Convert to PCB = yes/no`（E1 63 处，本案例未用 no 值）

### 语义实现

- `_is_dnp(c)`：两标志任一为 `no` 即 DNP；
- `resolve_nets_by_domain`：DNP 的 0Ω 跳线/短接符**不合并两脚域**（物理未
  贴装）；非桥器件本就不合并，行为不变；
- 输出标记：`pinmap --json` 元件行加 `"dnp": true`，非 json 行头加 `[DNP]`；
  bridges 输出加 `"dnp"` 字段且 `direct` 恒为 false。

### 实测（E1 DAC_AFE_A 页）

| 器件 | 标志 | 两脚网络 | 判定 |
| --- | --- | --- | --- |
| R235（0Ω） | Add into BOM=no | `1=DAC1_OUT_BUFF_A`，`2=''` | ✅ 不合并 + dnp:true |
| R136（0Ω） | （正常） | `1=2=DAC0_OUT_A` | ✅ 照常合并 |

bridges：该页 22 个两脚器件中 4 个 DNP（R235/R238 jumper、R5/R187 passive），
`direct` 全部 false。

## 六、修复优雅性复查（二次审查）

对前述修复逐项排查"回避问题"式处理：

**确认为回避并补修（1 项）**：
- `resolve_nets_by_domain` 的 `des2dnp` 只映射真实 Designator——短接符/
  NetFlag **无 Designator 属性**，合成位号 `SHORT{cid}` 查不到映射，
  DNP 短接符会被错误合并。已修：同时映射 `SHORT{cid}/PORT{cid}`。
  （两案例暂无 DNP 短接符实例——E1 119 个短接符全非 DNP、涡流 3 个亦然，
  属防御性修复，单元验证通过。）

**确认为正解非回避（6 项）**：属性遮蔽改名、`_norm_segs` 统一归一化
（4 消费点同源）、banner 入 stderr、0Ω 精确 token、DNP 不合并、
trace BFS 排序确定性。

**可辩护的取舍（如实记录）**：
1. **EproDB COMPONENT a[2] 归一化为空串**丢弃了符号 uuid 引用——实测
   Symbol 属性 **100% 覆盖**（E1 3575/3575 实例），信息完全冗余无损失；
   若未来出现无 Symbol 属性的 .epro 需补兜底（记录在案）。
2. **title←Name 兜底**使 LcedaDB NetFlag 的 symbol 列从空变为端口名
   （如 `+3.3V`）——增量改进，几何/网络零变化（netlist/pins 逐字节一致）。
3. **on_segment 共线容差 0.75**：有界启发式，仅服务"引脚压线段中间"的
   T 型场景（实测当前工程 0 例触发），为语义完备性保留。
4. **conn_nets 前缀+desc 关键词**：连接器在格式内无显式类型字段，启发式
   不可避免；已排除合成位号、覆盖 desc 关键词，且定位是"候选+人工确认"。

## 八、CBB 实例→模板链接调查与展开功能（追加）

### 8.1 文件内无链接信息（定论）

对 E1 逐层排查，**立创EDA 导出 .epro 时不携带复用块实例→模板页的关联**：

| 排查点 | 结果 |
| --- | --- |
| CBB1 实例全部原始记录 | 仅 Device(悬空 uuid)/Symbol(黑盒)/Designator/Name(空)/BatchReuse(空) |
| Device 引用（CBB1-5） | uuid **不在 devices 表**（悬空） |
| 黑盒符号 esym | 仅引脚定义 + `Designator=CBB?` 模板属性，无模板引用字段 |
| boards/schematics 条目 | 仅 schematic/pcb uuid，无 reuse 信息 |
| zip 条目 | 无 REUSE/* 相关文件 |
| config | 仅 title + cbbProject=false |

因此实例→模板只能**推断**：端口名集合匹配（黑盒引脚名 = 模板 NetPort 名）。

### 8.2 CBB 展开功能实现

- **匹配**：`--cbb-map 位号=板名或页名` 显式指定优先；否则按"端口名集合相等"
  匹配全部页。候选按**内容指纹**（位号+标题+器件型号的排序元组——用语义
  身份而非 uuid，使 `_old` 副本归为等价）分组：
  - 唯一组 → 采纳（多成员时选字典序最小并 stderr 说明）；
  - 多组歧义 → stderr 告警列出全部候选，不展开（如 CBB1-5 的三个电源
    模板端口同为 VIN/VOUT/GND/EN，无法自动区分）；
  - 无候选 → 告警。
- **展开语义**：模板内部连通域按端口映射，生成 `实例位号.模板位号` 条目
  （如 `CBB6.U13`），net 值 = 模板内部网络 ∪ 端口对应父网络（逗号并集）
  ——netlist/trace/netfind/nets/pins 的同名归并据此贯通 CBB 内部电路；
  模板内部桥接多端口的域会把多个父网络经展开条目连通。
- **限深**：嵌套 CBB 最多展开 2 层；PORT/SHORT 合成位号不作为展开条目。
- **边界**：`pinmap` 不含展开条目（仍是黑盒视图）；`find` 不索引展开位号
  （查 CBB 内部器件请直接查模板页）。

### 8.4 立创EDA 自身的展开机制（原始 .eprj2 逆向发现）

用户提供原始工程 `Piezo_Driver.eprj2` 后逆向确认：

- **新格式 .eprj2（分支版本化）**：`documents` 等主表为空，全部内容在
  `history_data`（base64 + **加密**，香农熵 8.00 bits/byte）+ 
  `project_structures.structure`（**明文 JSON** 工程树）。
- **`structure.blockSymbols` 就是复用块登记表**：
  ```json
  {"uuid": "cc6076fe...", "title": "_CBB_SMPS_TPS563201_BUCK_ONELAYER",
   "docType": 17, "source": "607a3976b169eaeb"}
  ```
  uuid = 黑盒符号 uuid（与实例 Symbol 属性一一对应）；title = 本地模板板名；
  source = 外部 CBB 工程引用（工程uuid|文档uuid，不在本文件树）。
- **编辑器展开链路**：实例 Symbol 属性 → blockSymbols[uuid] → source →
  外部 CBB 工程模板内容 → 按端口名对齐 flattening。
- **source 不在本地**、文档内容加密——新格式 .eprj2 的文档内容当前工具
  无法读取（已记录 TODO）；但 **structure 明文可读**。

### 8.5 利用 blockSymbols 的自动精确匹配

EproDB 打开 .epro 时自动探测**同目录 *.eprj2**，读取其
`structure.blockSymbols` 构建 `{Symbol uuid → 模板板名}` 映射（stderr 提示
条数）。展开匹配优先级：

```
--cbb-map 显式指定 > blockSymbols 符号映射 > 端口名集合匹配
```

验证：examples 目录放入 Piezo_Driver.eprj2 后，**15 个 CBB 实例全部自动
精确展开**（CBB1→SMPS_TPS563201、CBB2/3→TPS7A4901(U45/R219/C247-251)、
CBB4/5→TPS7A3001(U1/C1-C5/R2)、CBB6-9→MAX5318、CBB10-15→ADHV4702），
此前歧义的三个电源模板全部解开，无需 --cbb-map。

## 九、遗留

- `.epro2/.epru`（V3 增量日志备份）仍不支持（历史归档用途，优先级低）；
- E2 出现自定义属性（`测试点上BOM=否`）——非标准标志不参与 DNP 判定，
  如需可后续加自定义白名单；
- EproDB 的 CBB 页已可经 `boards`/页名访问（`_CBB_xxx::P1`），但多工程命令
  （netfind/trace/link-check/find/search）尚未在 .epro 上验证多开场景；
- CBB 展开的父侧引脚接未命名网络时不产生别名条目（无法按名关联）；
- `--cbb-map` 键为实例位号（全局），跨板同位号 CBB 指向不同模板时需分次分析。
