# CBB 母图位号映射调查（加密 .eprj2 2 段 INSTANCE 格式）

2026-09-09。调查加密 `.eprj2`（新版分支格式）的 CBB 复用块母图位号
能否从文件读取。**结论：数据在文件里，格式已定位，实例关联键待解。**

> 起因：发现加密 `.eprj2` 的 CBB 展开用模板位号（`CBB6.U13`），
> 而官方 `.epro2` 用母图位号（`CBB6.U2`）。曾误判为"文件里没有母图
> 位号"，被用户质疑（EDA 能正确打开并显示母图位号，数据必在），
> 深挖后推翻该错误结论。

## 1. 已确认的事实

### 1.1 两种格式的 INSTANCE 文档 uuid 不同

| 格式 | INSTANCE uuid 形态 | 段数 | `cbb_instances()` |
| --- | --- | --- | --- |
| 加密 .eprj2 | `<schematic_uuid>_$<page_uuid>` | 2 | 0（被跳过） |
| .epro2（官方导出） | `<sch>_$<page>~<inst_cid>_$<template_page>` | 3（含 `~`） | 65 |

样例：
- 加密 .eprj2：`120095be3ade3af5_$bc4b7a6e175284e5`
- .epro2：`0298ad21004bd80d_$58759deb39a23a10~b65b77a4bd3a9209_$91f2f32dd87f93f8`

`lceda_reader.py` 的 `Epro2DB.cbb_instances()` 要求
`len(parts) >= 3 and "~" in parts[1]`，故 2 段格式被整段跳过。
`Piezo_Driver_offline.epro2` 与加密 .eprj2 同为 2 段、`cbb_instances()=0`。

### 1.2 母图位号确实在加密 .eprj2 的 history_data 里

解密后 `INSTANCE_ATTR` 记录含 `Designator`（母图位号）：
```
{"type":"INSTANCE_ATTR","ticket":2433,"id":"e2"}||{"Unique ID":"gge260_4","Designator":"U27"}
{"type":"INSTANCE_ATTR","ticket":2433,"id":"e4"}||{"Unique ID":"gge261_4","Designator":"C133"}
```
- `id`（e2/e4/e12…）= **模板页元件 cid**（模板 `_CBB_MAX5318_2L::P1`：
  e2=U13、e4=C40、e12=C41…）
- `Designator` = **母图位号**（U27/C133/U26/C89…）
- 同一 2 段 uuid 下多个 ticket 段（2432/2434/2436/2438，各 22 条）。

### 1.3 与官方 .epro2 数据完全一致（决定性验证）

加密 .eprj2 `ticket=2432` 的 22 个母图位号集合，与 epro2
`cbb_instances()[(page=a43d16b468609165, cid=b65b77a4bd3a9209)]` 的
`members.values()` **差集为 0**（`ticket=2434` 同理匹配另一个实例）。
即两格式表达的是同一份母图映射。

### 1.4 结构表与实例节点不含此数据

- `projects.block_symbol_attrs_groups` = 空 `{}`。
- `project_structures.blockSymbols` 仅"符号 uuid→模板板名"（`source`
  为外部 CBB 库引用），无实例级成员映射。
- CBB 实例文档属性仅 `Symbol`/`Designator`/`NO_CONNECT`/`Relevance`。
- 模板位号（C40/U13）只在模板页元件属性。

## 2. CDP 活模型证据（ground truth）

`SCH.gVars.projectMgr.instanceAttrMgr.savedData` 只有 3 条，key 即 3 个
2 段 uuid，内容与文件 INSTANCE_ATTR 一致：
- `4f249e11..._$8a386fe3`（IsoInterface 页 sch_1）22 条，无 Designator
- `0298ad21..._$822c474a`（IsoInterface 页 sch_2）22 条，无 Designator
- `120095be..._$bc4b7a6e`（IsoInterface 页 sch）88 条：
  短 cid（e2/e4…）带 Designator + 长 cid（35a8d666…）仅 Unique ID 混排

`instanceAttrMgr` 原型方法：`get/getByPrefix/getWithInstanceDevice/
hasInstanceAttr/filter/...`；`getByPrefix('120095be3ade3af5')` 返回 0。

**CBB 实例（ControlDAC 页 e14754）活模型 children 仅 25 个**
（矩形+引脚），**不含展开的成员元件**——EDA 展开 CBB 是渲染/按需进行，
不在实例节点上存成员。

## 3. 未解点（下一步）

**INSTANCE 文档挂在 IsoInterface 页，但 CBB 实例在 ControlDAC 页**
（页 uuid 不同）。2 段 uuid 无 inst_cid，如何把某 ticket 段关联到具体
CBB 实例（如 CBB6 cid=e14754）尚未解码。

候选线索：
1. `ticket` 序列（2432/2434/2436/2438）与实例序号的对应；
2. Unique ID 的 `_N` 后缀（`gge260_4` 的 `_4`）可能与实例序号有关；
3. 页间引用关系（IsoInterface 页可能记录了它引用的 CBB 实例）。

**严禁记为"无法拿到"**——数据已确认在文件内，只是关联键待解。

## 4. 影响与临时方案

- 加密 `.eprj2` CBB 展开当前回退模板位号（`CBB6.U13`）；
  `.epro/.epro2` 用母图位号（`CBB6.U2`）。两种口径均"正确"但不同。
- 临时方案（未实施）：加密 .eprj2 展开 CBB 时 stderr 提示
  "本格式展开用模板位号（导出 .epro2 可获母图位号）"。
