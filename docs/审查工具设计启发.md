> 来源：2026-08-23~24 lceda_sch_reader 渲染/PCB 解析/字段字典开发过程复盘。
> 本文档是审查工具（sch_review_tool 下一步）的**需求输入与架构约束**。
> 每条原则附事件指针（探针脚本 / 提交 / 字典章节），可回溯。

## 一、九条原则

### 1. 审查结论必须带证据链，规则本身要分级
**原则**：每条 finding 附三件套——文件内原始证据（哪个记录/字段/值）、
规范依据（官方文档章节）、置信级别。规则库同构分级
【官方/实测/实证/推断·待验证】；无据阈值标注"启发式建议"且可配置。
审查工具自己制造冤案，比漏审更伤信任。
**事件**：字段字典 §0 修正日志（FONTSTYLE 斜体/加粗互换、ATTR[11]
误读"隐藏"、PCB COMPONENT 层位、Y 向上）；AGENTS.md"参数依据纪律"；
提交 de2b83f/568f096。

### 2. 审查读"设计意图"，而非"显示效果"
**原则**：EDA 文件是结构化设计意图（模板覆盖、公式属性、NO_CONNECT、
DNP、Unique ID）。审查工具的本质优势是读意图；前提是解析层先还原
意图——公式不解析则审查的是字面；PART 不匹配则引脚审查错库。
**事件**：公式 32 例实证与解析链（probes/dbg_formula_align.py、
dbg_formula_src.py，提交 568f096）；标题栏模板覆盖
（dbg_tb_mark.py）；_match_part；NO_CONNECT/DNP 语义（SKILL.md）。

### 3. 可视化是复核证据，不是审查本身——且必须先自证保真
**原则**：报告里的图（问题标注）供人工复核；渲染不保真时复核被误导，
引入第二类错误。可视化管线须先与 EDA 实际显示对照验证（截图/CDP），
渲染参数外置（为 web 交互审查铺路：SVG 点击器件看结论）。
**事件**：Y 向上修正前后对照（用户截图 2026-08-23，da_v3~da_v6 迭代）；
render_config.json 配置外置；提交 de2b83f/9ef7ae0/568f096。

### 4. 先建"工程有效性"模型，区分当前设计与历史残留
**原则**：真实工程含多 PCB 快照、跨板同名页、CBB 模板混页、废案存档。
审查前先解析工程层级与"当前有效设计"，否则把备份当问题报。

**机制实证（2026-08-24，probes/tmp/dbg_board_assoc.py）**——三种格式
的板关联存储差异：

| 格式 | 板关联存储 | 多板含义 | "哪个是当前" |
| --- | --- | --- | --- |
| .epro | 显式：project.json boards{name→schematic+pcb}（Piezo 16 板全有关联） | 多板=多设计并存（quadPizeo/dualPizeo/PowerBoard/_CBB_*/废案存档），**全部合法** | 无标记 |
| .epro2 | 显式：BOARD 文档 + SCH/PCB META.board；无关联的（"废"）归 free | 同上 | 无标记 |
| 新 .eprj2 | **显式**：project_structures.structure（base64+gzip JSON，层级 boards/schematics/sheets/pcbs/blockSymbols，每项含 board 归属 + zIndex + updateTime）——与 .epro2 同构 | 同上 | 无标记 |
| 旧 .eprj2 | **无存储**：boards 表空，PCB 无关联字段（涡流 5 个 PCB） | 不适用（同工程多 PCB 快照） | 纯启发式 |

**新版 .eprj2 补充**（probes/tmp/dbg_newfmt_boards*.py，2026-08-24）：
structure 顶层键 boards/schematics/sheets/pcbs/panels/blockSymbols，
每项含 `{uuid, title/name, board, zIndex, updateTime}`——板归属、
排序、更新时间齐备，与 .epro2 的 META.board 语义一致。
当前 LcedaDB.hierarchy() 未消费该表（旧版归 free 的处理对新版过于
保守），**待办**：解密后读 project_structures 最新 ticket 的 structure
补全新版板层级。

**关键认知**："当前有效"不是文件格式概念，是设计管理概念。文件存的是
归属（哪张图/哪块板属于哪个板），不存"哪个是活的"。审查工具应三级
区分并标注置信度：
1. **存储关联**（.epro/.epro2/新 .eprj2）：权威，直接用 hierarchy()；
2. **统计/命名启发**（旧 .eprj2 无关联时）：pcbsch"匹配数最多=主板"、
   命名模式（_1/_2 后缀=副本、_CBB_=复用块、含"废/备份"=弃用）——
   输出时标注"推断"；
3. **人工确认**：配置覆盖（如"当前板=PCB1"），工具不得静默假设。

**pcbsch 已标注板归属**（2026-08-24）：有存储关联时输出
`PCB「名」（板: 板名）`。实证价值：Piezo 工程 4 个 581 元件 PCB
互为副本，匹配数启发无法区分；板关联直接消歧——
quadPiezoDriverRev1_1.brd→板 quadPizeoDriver_RevA_1.1 才是最高版本，
其余 _brd_1/_2/_3/_4 属于 CBB 板/旧版板。

**PANEL/拼版**：structure.panels / project.json panels 键——立创EDA
面板设计功能，**不属于原理图审查范围，暂不处理**（TODO 在案；
openlceda 或 PCB 级审查时可能用上）。

**事件**：涡流 5 个 PCB 文档仅 PCB1 有效；Piezo 16 板含废案存档；
resolve_page 同名页 stderr 警告。

### 5. 跨格式/跨版本一致性是天然审查面
**原则**：多后端归一到统一模型后，同一规则跑任意格式；跨格式稳定键
（Unique ID）使版本间差异审查（器件/网络增删改）低成本可行，
价值高于单点检查。
**事件**：verify_all_formats 15 工程全过；epro2 备份 PCB2 与 SQLite
PCB2 同 125 元件全匹配（UID 跨格式稳定）；网络集合对比
（共同 81 / 仅 0 / 0）。

### 6. 规则开发 SOP：探针先行 → 规则实现 → 回归留痕
**原则**：先探针统计真实分布，再定规则，再实现；每条规则配
"应报/不应报"样例（修正日志即现成用例库）；改动必跑回归三件套。
**事件**：scan_field_inventory.py（全格式字段清单）→ 字典 → 实现；
render_smoke.py（7 工程）/smoke2.py/verify_all_formats.py；
AGENTS.md 回归纪律。

### 7. 机器可读输出是硬纪律
**原则**：审查报告供下游（CI/报告生成器）消费——stdout 只允许
结构化输出，横幅/警告一律 stderr，退出码有语义；调试打印不得
残留（含会 NameError 的半成品调试代码）。
**事件**：cmd_render 残留 [probe] print + 未导入 traceback
（audit_robust.py 抓获，提交 19ade27）；开发文档"json 输出 INVALID
→ 检查 print 到 stdout"排障条目。

### 8. 归一化边界划在后端，规则层只面对统一模型
**原则**：格式差异（字段布局、坐标系、原点、增量合并）只在后端内
归一化；审查规则不接触原始记录，否则规则库碎成"每格式一套"。
**事件**：PCB ATTR key/value 在 [7]/[8] vs SCH [3]/[4]
（字典 §1.5）；V3 epru→V2 转换（Epro2DB.sheet_records doc_type=3）；
esym HEAD.originX/Y；坐标 Y 向上翻转只在渲染发射处。

### 9. "工具自身配置"与"工程内配置"分清
**原则**：渲染/审查工具的主题、开关、阈值是工具配置（外置
render_config.json，_note 标注依据）；工程内 FONTSTYLE/ATTR 显示位
是用户排版意图（必须读取尊重）。二者混淆会导致发明排版/丢用户意图。
未来审查规则的阈值同样外置，且标注依据级别。
**事件**：硬编码字号翻车 → FONTSTYLE/ATTR 显示位 → render_config.json
（提交 568f096）。

## 三c、启发式审计（2026-08-24，probes/audit_heuristics.py）

**有结构化确定信息、已替换**：
| 启发式 | 结构化真源 | 状态 |
| --- | --- | --- |
| 0Ω 靠 title/desc 正则 | device/实例 attrs `Value`（实测 14/14 一致，分布干净如 "0Ω"/"100nF"） | ✅ Value 优先，正则兜底；Value 明确含非零数字直接否决 |
| pcbsch 主板=匹配数最多 | 板关联存储（四格式差异见原则 4） | ✅ 有关联即标注（板: 名） |
| 位号 fallback 摆放 | 模板 ATTR 显示位（len>=11 修复后命中） | ✅ |
| 属性公式字面 | device attrs 解析链 | ✅ resolve() |

**无结构化替代、保留（已文档化+置信度标注）**：
| 启发式 | 原因 |
| --- | --- |
| is_power_net 名称模式 | NetFlag(18) 附加可作辅助证据，但实测前 5 页 NetFlag 命名网极少（多数电源网是裸线名），提取成本>收益；trace --no-power 只影响展开范围不影响正确性 |
| CBB 端口集唯一候选匹配 | 旧格式无存储映射；只接受唯一候选+告警 |
| resolve_page 同名页取第一个 | 用户意图不在文件内；stderr 警告+--schematic 显式指定 |
| Epro2DB CBB 板标题匹配 | .epro2 导出无 structure 表，数据真缺 |
| fallback 位号摆放（模板也无 pos 时） | EDA 真实默认未实证（待 CDP） |
| trace depth=5 / max_labels=500 等限值 | 配置可调，非正确性参数 |

**渲染结点规则**：seg_count>=3（三线共端点）。中跨 T（线端落在另一线
内部）采样 0 例——LCEDA 用户在端点连接，与 EDA 截图一致，维持；
如未来观测到中跨 T 再加端点落段判定。

## 四、配置分层（工程配置 vs 个人/应用配置）

审查工具（以及未来 openlceda）的配置必须分两层，**不可混用**：

| 层 | 内容 | 存储 | 例子 |
| --- | --- | --- | --- |
| **工程配置** | 被审查工程内部的用户意图——EDA 用户在编辑器里摆的 | 工程文件内（FONTSTYLE、ATTR 显示位、LINESTYLE、模板覆盖、公式属性） | 字号/颜色/对齐、位号位置、网络名显示位 |
| **个人/应用配置** | 审查工具自己的行为——主题色、开关、阈值、规则集 | 工具目录 render_config.json / 未来 review_rules.json（_note 标依据） | 结点半径、NC 颜色、DNP 标记样式、显示项开关、审查严格度 |

**规则**：
1. 渲染/审查输出**优先读工程配置**（用户在 EDA 里看到的排版就是
   真值）；工程没存的才落到个人配置的默认值（默认值须实测/官方依据）。
2. 个人配置项全部 `_note` 标注依据级别（实测/官方/自创），web 渲染
   直接 fetch 同一份 json。
3. 未来 openlceda 的编辑器配置同理：**编辑器主题/偏好**（个人）≠
   **工程文档属性**（随工程走）——立创EDA 的 LINESTYLE null=继承默认
   就是这个语义，兼容实现时保持。

## 五、openlceda 愿景（远期，暂不实施）

目标：完全替换立创EDA（兼容其工程格式）。当前审查工具是经验积累期：
- 格式层：字段字典 + 三后端 + 解密管线 = openlceda 的读取底座
- 渲染层：SVG 渲染器 = openlceda 画布的雏形（缺交互编辑）
- 配置层：render_config.json 分层模式 = openlceda 偏好系统雏形
- 经验层：本文档 + 字段字典 + 探针库 = 避免重复踩坑

**兼容关键点（从开发过程提炼，实施时需逐项验证）**：
- 工程格式读写：.eprj2(SQLite)/.epro(ZIP)/.epro2(epru 增量日志)/
  新版加密——读已通，**写回未验证**（增量 ticket 合并、分支版本化
  是高风险区）
- 板关联：新/旧 .eprj2 差异大（structure 表 vs boards 表空），
  openlceda 保存时需写对格式
- 属性公式、模板覆盖、PART 分库、CBB 展开——语义必须与 EDA 一致
