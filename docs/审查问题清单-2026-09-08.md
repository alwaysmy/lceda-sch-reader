### C. 旋转/镜像坐标变换

- **现象（原判断）**：pinmap 与渲染两套实现、顺序相反。
- **状态**：❌ 已证伪 + ✅ 顺带修真实 bug
  - 90° 倍数下 pinmap 与渲染双公式在两工程 12933 个测试向量上**零分歧**；
    非 90° 旋转器件数为 0。
  - 真实 bug 是 **V3 引脚 tip 方向**：PIN 记录坐标是外端点（导线连接点），
    tip 公式算的是体侧 joint，旧 `-sin` 使竖直引脚 joint 76/77 脱边。
    `38e36fa` 改 `+sin`（竖直 joint 47/77 上边），C64 伪同点修正，
    `netlist` 零差异。

### D. round(x,1) 无显式容差 + 魔法数

- **现象**：坐标全链 `round(.,1)` 精确相等，另藏 `on_segment` 的
  `abs(cross) <= 0.75`（`lceda_reader.py` resolve_nets_by_domain）。
- **状态**：⬜ 待做。修法：容差参数化 + 标注命中来源。
- **备注**：实测 0.75 未造成误连（三级不中且距端点 ≤3 单位者 = 0）。

### E. V3 双候选 PIN 冲突检测

- **现象（原判断）**：root/tip 落不同网时取首个、掩盖一端。
- **状态**：❌ 已证伪（2026-09-08 精确测量）
  - Piezo 三格式：`rootNamed_tipNamed_diff`（真异网冲突）**= 0**。
    原"7 个冲突"是把 `rootNamed_tipNone`（root 命中、tip 落空——V3 正常
    行为）误算。
  - 三级都不中的引脚 552 个，距最近导线端点全部 > 3 单位 → 真悬空，
    非匹配漏。
- **结论**：无需加冲突告警；root/tip 同命名时才需比网络名，当前数据无此情形。
- **可选增强**：将来出现真冲突样本时再加告警，保留双候选逻辑即可。
