# Gerber 区域轮廓边界

本次改动只涉及可选制造比较器 `scripts/pcb_compare_exports.py`。
`lceda_pcb.py` CLI、`lceda-pcb-ir/1` 和原理图输出契约不变。

## 格式依据和实现范围

依据 [Ucamco Gerber 2026.05](https://www.ucamco.com/files/downloads/file_en/554/gerber-layer-format-specification-revision-2026-05_en.pdf)
第 4.10.1–3 节：区域轮廓须显式闭合；一个 G36/G37 中的独立轮廓分别填充后
取并集，不能用奇偶填充把第二个轮廓直接当孔。孔可以通过规范定义的 cut-in
连接到外轮廓，内外边界须保持一致的填充侧。

本解码器只接受全直线轮廓中的精确 cut-in：往返端点完全相同、方向相反，
全部桥接同为水平或同为垂直。移除成对桥接后，每个边界须为简单闭环，
环间不能接触或相交；桥只能在两个端点接触边界。检查嵌套深度、环方向和
桥接树结构后，显式构造外环、孔和不相连的填充区域。

这些步骤不进行坐标吸附、不移动端点、不用 `make_valid` 或 `polygonize`
推测拓扑。解析元数据新增 `contour_decodings`，记录图元来源、桥接/简单环
数量、处理方法和结果哈希；已有 `geometry_repairs` 继续记录真正的修复。
比较报告仍通过输入和实现哈希绑定具体版本。

## 严格拒绝与显式修复的区别

- 未闭合轮廓直接失败，不允许下层库或 Shapely 隐式添加末边；
  `--repair-invalid` 也不授权补线
- 嵌套 G36、没有 G37 的未结束区域、区域外 G37 直接失败，避免底层解析器
  丢弃部分区域后仍返回其他看似正常的图元
- 非完全重合、斜向、混合方向、悬空尖刺、错误环方向、边界相交等不会作为
  合法 cut-in 解码；若显式修复成功，仍有修复审计并保持 partial
- 含弧 cut-in、零长度线段、其他退化构造不进入这个严格解码器；没有新增
  对它们的格式有效性承诺

检查覆盖这些特定失真途径，不构成完整 Gerber 语法/数值规范检查器。
例如，空区域、只有移动命令的区域，以及缺少起始 D02 的构造仍可能被
下层解析器接受；本次没有添加对这些情况的完整语法校验。
离散曲线、制造误差、缓存新鲜度和实际生产条件仍要分别核验。旧比较结果
如依赖底层隐式闭合，应使用当前版本重新运行，不能沿用旧的成功标志。

合法 cut-in 可以在不产生修复的情况下完成几何比较；这不会改变原 IR 的
候选状态，也不会把 `manufacturing_verified` 改为 true。IR 不完整或其他
图元仍需修复时，整体比较仍为 partial。

## 合成回归

```sh
python -m pip install -r requirements-pcb-test.txt
python -m unittest discover -s probes -p test_pcb_export_comparison.py -v
```

测试全部使用生成的虚构几何：单孔、多孔、三层嵌套岛、轮廓反向/起点变换、水平/垂直
桥接、桥接分离填充区、透明孔、clear 极性、独立轮廓并集，以及未闭合、
嵌套、未结束、错误方向、局部重合、混合轴向和悬空尖刺等反例。
不需要用户工程或原生编辑器，也不代表增加了原生工程格式支持。
