# 原理图镜像与旋转的组合顺序

## 问题与修复

`_collect_pinmap_data` 原先先镜像引脚 X 坐标、再旋转。对于同时镜像并旋转
90°/270° 的实例，这与 COMPONENT 约定不同，会将引脚放到错误位置，表现为
空网、错误 peers，或者命中另一个位置的导线。0°/180° 的测试无法暴露这个问题。

现改为先旋转，再水平镜像，最后平移。主引脚位置和 V3 第二候选位置都经过
同一个实例变换；匹配仍依据已有导线顶点，不增加容差、不尝试多种姿态取命中
最多者，也不根据器件名称推测网络。

例如局部引脚 `(-13,7)` 在旋转90°后为 `(-7,-13)`，水平镜像后为 `(7,-13)`。
旧顺序得到 `(-7,13)`，二者不同。此处为后端已经归一化的相对坐标；本次不改
原点、Y轴、引脚方向、PART选择、日志重放或非直角旋转的既有处理。

## 依据与契约

- [官方 V2 COMPONENT 文档](https://github.com/easyeda/easyeda-pro-file-format-v2/blob/main/docs/en/schematic/component.md)
- [官方 V3 COMPONENT 文档](https://prodocs.easyeda.com/en/format/schematic/component/)
- 仓库 `reference/原理图文档格式.pdf` §3.3.2、
  `reference/lceda-pro-file-format-v3_2025.10.21.md` 的 Component 图元章节

上述规范均规定旋转、水平镜像、平移的顺序。现有原理图渲染内部 `T()` 已采用
此顺序，未修改其图形路径。辅助函数 `_xf` 的顺序和说明同步修正；它与电气
路径的旋转精度不同，不能再声称对所有角度完全等价。

原有“两个公式在已有样本上无差异”的历史记录不能证明组合顺序可交换。
缺少镜像直角组合或只对比相同公式，都不足以覆盖该边界；新增非对称例子
直接验证绝对位置和网络归属。

## 验证边界

公开回归均为虚构数据，枚举0°/90°/180°/270°及镜像开关，分别生成
`.eprj2`、`.epro`、`.epro2`，验证引脚坐标、连通域和 CLI pinmap。
另验证 V3 第二候选也使用同一变换，以及仅存在于旧错误位置的诱饵导线不会
被连接。用户工程和网络标识不进入测试夹具或公开验证记录。

```sh
python -m unittest discover -s probes -p test_reader_portable.py -v
```

本修复不代表完整电气签核。空网仍可能来自没有命名、实际未连接、显式NC或
其他读取边界，应结合源几何和正式输出核查。V3 `symbol_records` 的渲染退化
是独立未完成项，本次没有将其标为已解决。
