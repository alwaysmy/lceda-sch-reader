# 同名页解析 Bug 修复说明（uuid 键化）

- 日期：2026-08-18
- 涉及文件：`lceda_reader.py`
- 状态：已修复并回归通过，本文档供 review

## 一、现象与发现经过

在对比新旧版原理图工程（`涡流传感器.eprj2` 与 `涡流传感器-V1.0-2026.04.01.eprj2`）时，
`pinmap`/`components` 等命令输出显示 `schematic1` 与 `schematic1_2` 两块板的内容**完全相同**，
一度误判为新工程存在"重复图"。

经核查（直接查询 documents 表），两块板确实各有一张名为 `激励输出和AD采集` 的页，
且为**独立记录**（dataStr 长度不同），并非重复。真正的重复出现在**工具读取逻辑**：

工具按页名（`display_title`）读取页内容，而 `display_title` 在库中**不是唯一键**
（同一工程可存在多张同名页，分属不同 schematic）。同名页永远命中第一条记录，
导致 `--schematic schematic1_2` 参数看似指定了板，实际读出的仍是 `schematic1` 的页。

## 二、根因

1. **`LcedaDB.sheet_text` / `sheet_records`**：查询条件为
   `WHERE docType=? AND display_title=?`，同名页返回第一条；
2. **`resolve_page`**：按 `title == page_name` 匹配后返回 **title 字符串**，而非唯一键；
   `--schematic` 过滤后仍用 title 查库，等于过滤了个寂寞；
3. **遍历型命令**（boards/components/netlist/find/trace/search/bom 等）：
   循环 `db.sheets()` 拿到 `(uuid, title, sch, dt)` 后，却用 `title`（非唯一）去
   `parse_sheet`/`sheet_records`，同样命中错误记录。

## 三、修复方案：以 document uuid 为读取键

`documents.uuid` 在库内全局唯一，同名页可精确区分。

### 3.1 数据层（LcedaDB）

`sheet_text` / `sheet_records` 改为 **uuid 优先、display_title 回退**：

```python
row = self.cur.execute("SELECT dataStr FROM documents WHERE uuid=?", (doc_key,)).fetchone()
if row is None:
    row = self.cur.execute(
        "SELECT dataStr FROM documents WHERE docType=? AND display_title=?",
        (doc_type, doc_key)).fetchone()
```

uuid 查不到（旧调用、用户直接传页名）时行为与原来一致，**向后兼容**。

### 3.2 数据层（EproDB，.epro ZIP 后端）

- `_build_page_index` 增加 `page.uuid -> (sch_uuid, page_id)` 索引（原仅 `板名::页名` 复合键）；
- 新增 `sheet_text(doc_key)` 方法（原来缺失，`cmd_search`/`cmd_raw` 对 .epro 会 AttributeError）；
- `sheet_records` 改为经 `sheet_text` 复用，同时支持 uuid 与复合标题。

### 3.3 页解析层

- `resolve_page` 改为返回 **document uuid**；匹配逻辑兼容 EproDB 的 `板名::页名`
  复合标题（`title == page_name or title.endswith("::" + page_name)`）；
- `parse_sheet` 参数改名 `doc_key`，内部透传。

### 3.4 命令层

所有读取页内容的地方统一改用 uuid：

| 命令/函数 | 原键 | 新键 |
| --- | --- | --- |
| cmd_pinmap / cmd_nets / cmd_pins / cmd_attrs / cmd_raw | `resolve_page` 返回的 title | uuid |
| cmd_boards / cmd_components | `parse_sheet(db, title)` | `parse_sheet(db, uuid)` |
| cmd_netlist / cmd_find / _netfind_one | 同上 | 同上 |
| cmd_search | `db.sheet_text(title)` | `db.sheet_text(uuid)` |
| cmd_bom | `parse_sheet(db, title)` | `parse_sheet(db, uuid)` |
| _trace_one / _trace_multi / _conn_pairs | title | uuid |

`cmd_components` 的 `--sheet` 过滤增加复合标题兼容
（`st.endswith("::" + args.sheet)`），供 EproDB 使用。

> 说明：`resolve_page` 不带 `--schematic` 时仍取**第一个匹配**（与原行为一致，向后兼容）；
> 同名页存在时应显式传 `--schematic` 消除歧义。

## 四、验证

### 4.1 同名页区分（新工程）

| 命令 | 输出 |
| --- | --- |
| `pinmap 激励输出和AD采集`（无 --schematic） | 116 元件（第一个匹配 = schematic1） |
| `pinmap 激励输出和AD采集 --schematic schematic1` | 116 元件 |
| `pinmap 激励输出和AD采集 --schematic schematic1_2` | 109 元件，内容不同 |

同名页已可区分，两块板内容确实不同（修正了"重复图"误判）。

### 4.2 全量回归

`smoke2.py`（覆盖 list/boards/components/pinmap/nets/pins/search/datasheets/
netlist/find/trace/bom/attrs/raw/devmap 等命令的旧工程路径）——**ALL: PASS**。

## 五、遗留事项

- 不带 `--schematic` 的同名页仍返回第一条（默认行为）；文档/help 已注明同名页场景
  建议加 `--schematic`。
- EproDB 的 `sheets()` 标题为 `板名::页名` 复合格式，用户直接按页名传参时
  命令层已做 endswith 兼容；`cmd_components --sheet` 同理。
