# 电气规则层实现说明（2026-09-15）

> 依据：`docs/电气规则层建议-2026-09-15.md`（V2 模拟输出削顶排查反推的规则清单）。
> 本文记录**实际落地**的模块、判据、数据边界与验证结论。

## 一、落地了什么

| 模块 | 职责 | 分层位置 |
| ---- | ---- | -------- |
| `lceda_attrs.py` | EDA 属性串 → 规范键 + SI 量值（Quantity） | **语义归一化层**（新增类别） |
| `lceda_netgraph.py` | 元件角色分类 + 受引导遍历 + 反相级传递函数 | 模型层（衍生模型） |
| `lceda_rules.py` | 规则引擎（R1~R4）+ 端子包络表 | **规则层**（Phase 3 提前落地） |
| `review_rules.json` | 阈值/启停（外置，`_note` 标依据） | 配置层 |
| `review` 命令 | CLI 入口（text/json/`--table`/`--rules`/`--pages`） | 命令层 |

**关键分层判断**：属性串不是"后端格式差异"（V2/V3/epro2 三种后端吐出的都是
同一串中文属性），故**不能**放进后端做归一化——它是独立的一类
「语义归一化」。这与《设计启发》原则 8（格式差异归一化在后端）不冲突：
原则 8 管容器差异，本层管语义量值。

## 二、判据与数据边界（重要）

### R1 端子/输出电气包络 vs 钳位件起始
- 驱动上限 = `Vref × (1 + Rf/Rin)`（反相级，Vin=0 处即最高输出）。
- 钳位起始 = `VBR_min`；**双向 TVS 加 V_F≈0.7V**（反串联结构，见 `lceda_attrs.BIDIR_TVS_VF`）。
- 判据：`余量 = 钳位起始 − 驱动上限`；`<0` ERROR、`<0.5V` WARN（阈值外置）。
- 多个钳位件时取**钳位起始最低者**（最先导通、最先限幅）——不能取"跳数最近"
  （实测 U19 输出同挂 D11(18V) 与 D12(5V)，最近的是 D11 但真凶是 D12）。

### 数据边界（务必知悉）
1. **工程文件里通常只有 VBR 典型单值**（如 `击穿电压:7V`），**没有** datasheet
   的规格带（`6.4~7.0V`）。因此规则按典型值算，得到 U16 钳位 7.70V；
   实测 7.28~7.48V 落在规格带内。**量级一致**，足以在评审阶段拦截，
   但不追求与实测逐点吻合。
2. **"设计范围"不在原理图里**（来自需求/固件）。R1 用
   `驱动可达上限` 作客观上界，**不依赖**需求输入即可判"钳位是否吃掉量程"。
3. **无规格输入时**输出 INFO（说明可达上限与钳位起始），有阈值配置才出
   WARN/ERROR——不会在信息不足时乱下结论。

## 三、实测对照：V2 信号板

```
== 电气规则审查（122 元件 / 36 网络；2 ERROR / 0 WARN / 6 INFO）==
  [ERROR] R1  U16  驱动可到 10.36V，D8 钳位起始 7.70V —— 上端 2.66V（26%）不可达
  [ERROR] R1  U18  驱动可到 10.36V，D10 钳位起始 7.70V —— 上端 2.66V（26%）不可达
  [INFO ] R1  U19  驱动级输出包络不可算（T 型网络）→ 人工确认
  [INFO ] R3  +13.6V/+3.3V/−3.9V  未发现可见源（板外供电）
  [INFO ] R4  U16/U18  反相放大 → 固件映射需反相
```
- 与实测故障吻合：文档实测"27% 码值范围被压平"，规则给 26%。
- **U16/U18 增益 4.286 / 输出 10.36V 与人工手算完全一致**（0 误差）。
- **U19 是 T 型网络**（R73/R74/R75/R76 四点式），简单两电阻模型会算出错误的
  gain=7.27 并标 high——实现改为**识别 T 型后降级 low 并拒绝给值**，
  宁可不报也不错报。

## 四、受引导遍历（与朴素 BFS 的关键差别）

从端子向内找驱动级**不能**用朴素 BFS：实测对 U16 做朴素遍历会从其它引脚
涌入 `+13.6V/−3.9V/+1.96V-REF` 等大网，既找不到钳位件也到不了端子。

实现 `NetGraph.walk` 只跨**无源串联件（R/L/磁珠/PTC）**与（可选）**模拟开关**，
且**不进入电源/地网**。实测 V2 端子网络 `U_TEMP_SENSOR` 的遍历链：

```
U_TEMP_SENSOR ─F1(PTC)─ n1 ─L3/L4(磁珠)─ U15(开关)─ R67 ─ U16.OUT
     (0跳)              (1跳: D8/D7 钳位件在此)      (5跳: 驱动级)
```

**跨页连接靠"网络端口同名"**（`U_TEMP_SENSOR` 在 DA输出调理页与模拟输出页
同名即同网）——这是跨页信号能走通的关键，实现里网络键**优先用网络名**。

## 八、多通道运放支持（2026-09-15 补充）

`channel_pins()` 按通道后缀拆引脚（实测 OPA2350：`OUT A/OUT B/IN A±/IN B±`），
每通道独立算传递函数，取第一个 high；这样多通道运放不会因引脚名带通道字母
而被误判为"非驱动级"或算错通道。v4 工程（STM32-DAQ-v4）的 U3 实测：
通道 A 正确切出 `{IN+, IN-, OUT}`，V2 的单通道件行为不变（回归 PASS）。

## 十、架构修正：三层分层（2026-09-15 第二批，按用户指示）

**问题**：初版 `lceda_netgraph.driver_transfer` 把"识别拓扑"与"套公式"揉在
一起、硬编码两电阻模型——识别不了就降级放弃。这是"限定模型"。实测反例：
V2 的 U19 反馈网络是 R73/R74/R75/R76 + C98/C100/C101 + L8 的复合网络，
任何预设公式都覆盖不全。

**改成三层**：

```
第1层 电路块识别  lceda_blocks.py  认出 follower/inverting/non_inverting/
                                    integrator/SK-LP/SK-HP/MFB/comparator/
                                    t_network/opamp_network(兜底)
第2层 网表导出    lceda_spice.py   **无条件**导出（不依赖识别成功）：
                                    运放行为模型/TVS反串联/电源源/无源件
第3层 计算或仿真  公式 + LLM/SPICE  简单块套公式；复杂块交 LLM 跑 SPICE
```

**第 1 层**：只负责"认出是什么块"，认不出就标 `opamp_network`（不报错），
保留 `evidence` 与 `confidence`。已实现块的种类与判据见 `lceda_blocks.py` 表。

**第 2 层**：从驱动 OUT/IN± 出发按**网络邻域**聚合元件（2 跳展开），
所以即使第 1 层没认出，网表依然完整——实测 U19 的 4R+3C 全部导出。

**第 3 层**：`evaluate()` 对有闭式解的块套公式（反相级增益/偏置、
SK 的 fc/Q、积分器时间常数）；其余交 LLM/SPICE。**不要求全自动**（用户
明确指示）——`features()` + `emit_for_block()` 提供结构化输入。

**净图不再自带公式**：`netgraph.driver_transfer` 改为**委托** `blocks`，
消除两份实现漂移（此前正是双份公式导致 T 型判据不一致）。

## 十一、识别判据的两个实测陷阱（已修正）

1. **电源去耦电容会污染支路计数**：U16 的求和节点邻域含 C82/C84 等电源
   去耦，早期"数支路数"把最简反相级误判成 T 型。**修正**：只数**电阻**支路，
   且排除通向电源/地网的支路。
2. **IN- 隔离电阻不是增益支路**：U16 的 R66(3.9k) 连 IN- 自身，运放输入
   无电流故不影响直流增益（文档公式里也不出现）。**修正**：排除"通向驱动
   自身输入引脚网"的电阻，否则最简反相级会被否掉。
3. **T 型判据**：Rin 通向的输入节点上若**还挂着别的电阻**，说明是两级/T 型
   网络（U19 实测），交网表而非硬套两电阻公式——**宁可不报，不给错值**。

## 十三、可扩展结构与验证状态标记（2026-09-15 第三批）

### 13.1 注册表化（"逐渐拓展"）

识别器与公式改为**注册表**，内置项 + 可添加项：

```python
# lceda_blocks.py
RECOGNIZERS = []        # [Recognizer(kind, fn, priority, verified, note, source)]
FORMULAS    = {}        # kind -> Formula(kind, fn, verified, note, source)

register_recognizer(kind, fn, priority=50, verified=..., note="")
register_formula(kind, fn, verified=..., note="")
load_extensions()       # 加载工具目录 block_ext.py（可选）
registry_info()         # 自省：有哪些能力、验证状态、来源
```

- **识别顺序**由 `priority` 决定（小者先试）：10=SK/MFB（结构特征最明确，
  且 OUT↔IN- 可能同网须先于 follower）/20=跟随·积分/30=同相·反相/
  90=T 型（判据最宽，兜底归类）/95=比较器。
- **加新拓扑不必改 `lceda_blocks.py`**：在工具目录放 `block_ext.py`，
  顶层调用两个注册函数即可；`source` 自动标为 `ext:<文件名>`。
  参考模板见 `block_ext.example.py`（含契约说明与"只在充分时给 high"
  的纪律）。
- CLI：`review --blocks-cap` 列出全部能力与验证状态。

### 13.3 与外部 SPICE 仿真的关系

三层里第 3 层是"计算**或**仿真"，两条路并存而非二选一：

- 有闭式解的块 → 内置公式直接算（快、可回归）；
- 无闭式解或参数不全的块（如 `t_network`/`mfb_lp`/扩展新拓扑）→
  **第 2 层网表**（`--netlist <位号>`）交 LTspice/ngspice 或 LLM 算。
- 因此**新增能力有两条落地方式**：写识别器+公式（进注册表），
  或只写识别器、由网表交外部仿真。后者不需要公式就能用。
