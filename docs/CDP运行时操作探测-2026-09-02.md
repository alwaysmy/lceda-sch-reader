# CDP 运行时操作探测 — 配置/工程创建/原理图创建/CBB（2026-09-02）

> 目标：CDP 连接运行中的立创EDA专业版 V3.2.175，实证四类操作的内部调用链：
> **配置保存、工程创建、原理图创建、复用模块(CBB)创建**。
> 方法：渲染层 hook（`messageBus.publish/rpcCall` + `fetch/XHR` + `Worker` +
> `localStorage.setItem`）后驱动 UI 与 `SCH.doCommand`，全量记录真实调用流。
> 探针：`probes/cdp_probe.py`（harness，eval 结果可存文件）；捕获数据在
> `probes/tmp/*.json`（gitignored，本文档已摘要固化）。

- 版本：JLCEDAPro **3.2.175.ef8ca094**（Electron 41.2.1 / Chrome 146），

## 四、工程创建（开始页 → 新建工程，全链路实测）

UI 填写 `{name, 简介, 路径}` → 点保存后捕获：

1. `mb.pub /pro-mgr/new/cloud/create` `{message:{project:{name, introduction,
   description, public, user_uuid, ownerSelectId, cbb_project, ...}}}`
2. `rpcCall notLegalTitle ["<名>",1,128,false]` —— 名称合法性校验
3. XHR `POST /api/client/createProject` —— 云端建工程记录
4. XHR `POST /api/client/openProject`
5. XHR `GET /api/v4/projects/<uuid>`（多次，拉详情/分支）
6. `mb.pub /pro-mgr/project/create/succeeded {uuid, name, cbb_project, path}`
7. 打开序列：`waitWorkerReady` → `/pro-ui/hash/add/id <uuid>` →
   `/pro-mgr/project/open {message:{uuid, options:{needProgress,isNew}}}` →
   **`new Worker("editor?entry=mgr-project-worker.js")`（每工程一个 project-worker）** →
   XHR `/api/client/projectPaths?refresh=yes` → 进度条至 100%

**新建工程自动初始化**（project_structures.structure 实证）：`Board1` +
`Schematic1`（含页 P1）+ `PCB1` + `Panel1`，以及 CONFIG 文档与
`default_sheet` 图框器件。同名"块符号"机制：每个 Schematic 名下自动生成
symbol/device 对（`/PrjDB/symbol/getDataByTitle ["Schematic1"]`）。

磁盘：保存前 .eprj2 仅含空表+projects 行；保存后见 §6 加密发现。

## 五、原理图创建（`SCH.doCommand('new_schematic')` 实测全链路）

`doCommand` 分发器（173 个 case，完整清单 probes/tmp/docommand_all.json）
含 `new_project/new_schematic/new_page/new_board/new_PCB/new_waveform/new_CBB/
file_save/save_all/openCBB/checkERC/check_in/check_out/generateOrUpdateBlockSymbol(2)/
editBlockSymbol/lib_*/clear_autoBackup_project` 等。

new_schematic 捕获序列（本地打开的工程走 local 变体）：

1. `rpcCall ui/checkProjectPublish`
2. `rpcCall /PrjDB/project/startBatchUpload [projectId]` —— **批量提交事务开始**
3. `rpcCall /pro-mgr/new/local/schematic` `{uuid: projectId,
   data:{name:"Schematic2", board:""}, options:{createSheet:true}}`
   —— 一次调用同时建 schematic(Schematic2, uuid 8e5f046c...) + 首页 p1
   （对应云上创建走 `/pro-mgr/new/cloud/schematic`，同形参）
4. 一系列读：`/PrjDB/schematic/getData`、`/PrjDB/sheet/getAllArrDatas`、
   `/PrjDB/sheet/getLotsArrDatas`、`/PrjDB/symbol/getDataByTitle`
   （新建的 Schematic2 也查块符号）
5. `/pro-mgr/project/updateData/schematic/update`
6. `openDoc {tabId:"<sheetUuid>@<projectId>", path: projectId, uuid: <sheetUuid>}`
7. `sch/createDoc {data:{uuid, project_uuid, title:"p1", display_title:"P1",
   modifier:{...用户}}}` —— 渲染层文档模型创建
8. `/pro-ui/container/tab/active {tabId, containerId:"editor-window-main"}` +
   `/pro-ui/container/tab/active {containerId:"leftProjectDesignTab", tabId:"pages"}`
9. `rpcCall /CommonDB/log/setData [{type:"New Page", content:[{"Schematic Name":
   "Schematic2","Sheet Name":"P1"}], project_uuid}]` —— **操作日志/历史记录**
10. `rpcCall /PrjDB/project/endBatchUpload [projectId]` —— 事务结束

## 六、保存流程与新版加密 .eprj2（重要格式发现）

`SCH.doCommand('file_save')` 捕获：`/PrjDB/project/getData` → `isArchive` →
`/pro-ui/judgePermission {type:"project_document_update"}` →
`/CommonDB/log/setData {type:"Save", ...}` → `getCanvasPreviewImgData
{width:1920, height:1360, maxSize:307200}`（缩略图）→
`/pro-ui/generatePreviewImage` → `/PrjDB/project/getDocMaxTicket` →
`/pro-mgr/api/branch/list`。

**落盘形态（实测）**：V3.2.175 新建的 .eprj2 保存后
- `documents/schematics/boards/components/devices` 主表**仍为空**；
- `project_structures` 写入 1 行（ticket=320）：`structure` JSON = 权威工程树
  `{boards:{...Board1}, schematics:{Schematic1,Schematic2}, sheets:{P1,P1},
  pcbs:{PCB1}, panels:{...}}`，每项带 `source/version/updateTime`；
- `history_data` 写入加密增量 blob（base64 解码后熵 7.24，无 gzip 魔数，
  **AES 类加密**）；`db_versions: {sqlite: "25.10.31.1"}`。

→ **实锤：V3.2.175 新建工程即"新版加密 .eprj2"**（正是 README/TODO 中
"documents 表空、内容加密 → 明确报错指引导出"的格式），且内容落点已定位：
结构在 `project_structures.structure`（明文 JSON），文档内容在
`history_data.dataStr`（加密增量，uuid 相同多段=`uuid-1` 续段）。
静态解析不可行，CDP 导出走 `getSourceCode()` 仍有效（见
CDP调试立创EDA-2026-08-21.md）。老 .eprj2（V2.2 快照格式）不受影响。

## 七、复用模块（CBB）创建

- 入口：开始页"新建复用模块"或 `doCommand('new_CBB')`；对话框字段
  `{复用模块名, 描述, 路径}`，默认路径 `Documents\LCEDA-Pro\libraries`。
- 捕获序列：`ui/checkProjectPublish` → `notLegalTitle` →
  **`/pro-mgr/new/cloud/project` `{project:{name, description, public:false,
  cbb_project:true, tags:[], editorVersion:"", path:...libraries,
  notChangeClientCreatePrjPath:true}}`** → `/pro-mgr/project/tempOpen {uuid}`。
- **CBB = `projects.cbb_project=1` 的独立 .eprj2 工程**，存 libraries 目录
  （实测 `libraries\CDP探针-临时CBB.eprj2`，projects 行第5列 cbb_project=1）；
  刚创建时所有内容表为空，需在 CBB 编辑器内绘制/保存。
- 相关既有结论印证：CBB 放置=docType 17 符号；使用侧命令 `openCBB`/
  `generateOrUpdateBlockSymbol(2)`/`editBlockSymbol`；
  RPC 常量 `CBB_AS_CLOUD=/pro-mgr/cbbAsCloud`、`CREATE=/pro-mg/cbb/create`、
  `DOWNLOAD_CBB=/pro-mgr/export/download/cbb`、`CBB_LIST=/api/cbbProject`、
  `UPDATE_REUSE_BLOCK=/pro-mgr/updateReuseBlock`。

## 八、RPC 主题命名空间（static+运行时归纳）

- `/PrjDB/<entity>/<op>`：entity ∈ attr,blob,board,componentGroup,copper,
  device,font,footprint,panel,pcb,schematic,sheet,simulation,symbol,variant,
  project,config；op ∈ getData,addData,updateData,delData,createData,
  getAllKVData(s),getAllArrData(s),batchDelete,tryRename,isRename,
  getIdByName,isExist,getMaxTicket,getDocMaxTicket,savePendData,
  startBatchUpload,endBatchUpload,compress,flowWrite...
- `/pro-mgr/new/{cloud,local}/(create|project|board|schematic|sheet|pcb|panel|simulation)`
- `/pro-mgr/api/...`（分支/权限/备份等）、`/pro-mgr/project/(open|close|
  tempOpen|beforeClose|create/succeeded|config/onUpdate)`
- `/CommonDB/log/setData`：操作日志（type: "New Page"/"Save"/...）
- 云 HTTP：`/api/client/createProject|openProject|config|projectPaths`、
  `/api/v4/projects/...`、`/api/v4/documents/checkin|checkout/{project}/{branch}`

## 九、对解析工具的影响

1. 新版加密 .eprj2 的判断依据可从"documents 空"细化为：
   `db_versions.sqlite >= 25.x + project_structures 有行 + history_data 加密`。
2. `project_structures.structure` 是明文工程树，加密格式下也可离线读出
   **层级/页清单/版本号**（当前 detect_backend 报错前可先吐出这部分元信息）。
3. `web.db` 的 `db_paths` 表 = 全机工程注册表，`--eprj` 自动发现可用它兜底。
4. CBB 的 `.eprj2` 与普通工程同构（cbb_project=1），后端无需特判文件层面。
