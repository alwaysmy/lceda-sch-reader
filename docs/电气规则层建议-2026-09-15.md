# 电气规则层建议（2026-09-15）

> 来源：V2 信号板"模拟输出上端削顶"排查（结论见 E_distance 仓库
> `2_mcu_fw/dis_fw_v2_uart4test/5_docs/模拟输出削顶机理分析_2026-09-15.md`）。
> 本次是**靠板子 + 示波器 + 手搭 LTspice** 才定位的，过程反过来暴露了工具的能力边界。

---

## 0. 一句话结论

本次缺陷的性质是——**连接关系全对，电气量冲突**：
运放级按设计要输出 +10.4 V，而端子上挂的 5 V TVS（击穿 6.4~7.0 V）把它按在 7.3 V。

现有命令能回答"**谁连谁**"（netlist / pinmap / trace / polar 都很扎实，本次定位全靠它们），
但回答不了"**这级到底能输出多少伏**"。建议在既定的 Phase 3 规则引擎里加**一层"电气包络"规则**：
用器件属性里的量值（增益、参考、钳位、额定）算出每个端子的**实际可达范围**，再与设计意图/需求对照。

**这类规则不需要板子、不需要固件、不需要人肉仿真**——是"提前预见问题、减少软件测试"性价比最高的一层。

---

## 1. 先把本次的定位过程拆开（用来看哪一步可以自动化）

| 步骤 | 手段 | 可自动化？ |
| ---- | ---- | ---------- |
| ① 发现现象：端子被压在 7.28/7.48 V 平台 | 示波器实测 + 固件钉值 | ❌ 必须上板 |
| ② 取拓扑：三路输出级的引脚级网络 | **工具 `pinmap`/`components`** | ✅ 已具备 |
| ③ 手算传递：`V=1.96(1+Rf/Rin)−(Rf/Rin)Vin` | 人脑 KCL | ✅ **可自动**（结论与实测吻合 0.2%） |
| ④ 锁定限制者：逐器件看属性 → TVS VBR=7V | 人眼看属性串 | ✅ **可自动** |
| ⑤ 复现与验证 | 手搭 LTspice 网表 | ✅ **可半自动**（网表导出） |
| ⑥ 给修型建议（换 12 V 档 TVS） | 仿真 | ✅ 可半自动 |

→ **③④ 是最贵也最可自动化的两步**，而且恰好是本项目 **6 个模拟输出级全部适用**的通用形态
（"运放 + 反馈网络 + 端子保护件"）。把这两步做成规则，评审阶段就能拦住，不必等上板。

## 2. 建议的规则（按性价比排序，可直接落进 Phase 3 的 `{id, scope, check(ctx), severity, evidence}`）

### R1 端子电气包络 + 钳位冲突（★最高，本次直接命中）

- **输入**：引脚级网络 + 器件属性
- **算法**：
  1. **识别驱动级**：运放符号 + 环绕它的反馈电阻网络 → 算 DC 增益与偏置
     （本工程 3 种形态：`Rf/Rin` 反相、T 型网络反相、跟随）
  2. **在输出网络上找钳位件**：TVS / 齐纳 / 二极管到 GND 或轨 → 取 `VBR`、`Vrwm`
  3. **找串联件**：磁珠 / PTC / 限流电阻 → 取 `Isat`、`Ihold`、功率
- **输出**：每端子一行 → `设计范围 / 钳位起始 / 实际可达 / 负向能力 / 冲突`
- **判据**：`设计上限 > 钳位起始(VBR_min)` → **WARN「输出量程被保护件吃掉」**
- **本次若跑过 R1 会得到**：

  | 端子 | 驱动 | 设计上限 | 钳位件 | 实际可达 | 结论 |
  | ---- | ---- | -------- | ------ | -------- | ---- |
  | VOUT | U19 + R73/R74/R75/R76 | +10.5 V | D12 SMAJ5.0CA (VBR 6.4~7.0 V) | **+7.3 V** | ⚠ 上端 27% 不可达 |
  | U_TEMP_SENSOR | U16 + R63/R65 | +10.36 V | D8 同上 | **+7.3 V** | ⚠ 同上 |
  | U_TEMP_CONTROLLER | U18 + R68/R70 | +10.36 V | D10 同上 | **+7.3 V** | ⚠ 同上 |

  → 评审时一行告警，省掉整条"上板→示波器→手算→仿真"链。

### R2 串联器件能力 vs 最坏电流

同一网络上的磁珠（本次 MLZ1608M4R7，`Isat=120 mA`）、PTC（`Ihold=200 mA`）、
0 Ω/小阻值电阻的功率，与**驱动级可能灌出的最大电流**（运放短路能力 / 最低负载阻抗）比对。
本次 TVS 导通时电流路径 = 运放 → R67 → 开关 → 磁珠 → TVS，正好是这类检查的典型场景。

### R3 电源轨来源与参考脚核对

- 每条电源网列出**源器件**（稳压器/电荷泵/二极管/连接器），并标出**"没有可见源"的轨**
- 标出**参考脚不接系统地**的器件（本次电源板 ADM660 的 `GND` 脚接 +6.8 V、
  `V+` 接 +13.6 V、`OUT` 接 GND——这是刻意的浮动参考接法，但**从网表完全看不出来**，
  我在这上面卡了很久，最后是靠"用户确认电源轨正常"才绕过去）
- 判定：`无源轨` / `浮动参考器件` → 标注"需人工确认拓扑"，附 datasheet 引脚表

### R4 反相/极性语义提示（供固件映射对照需求）

输出级增益为负 → 直接提示"**软件映射需反相**"。
本次固件按 `0~100 ℃ → 0~2.5 V` 正向映射，而端子实际是**反相**的（100 ℃ → −0.35 V），
与需求文档里"模拟输出范围 0~10 V"的正相关描述冲突——这类**"硬件极性 vs 需求语义"**的
矛盾完全可以在评审阶段用一张极性表拦下。

### R5 接口规格书自动生成（把 R1~R4 汇总成一张交付物）

每端子一行：驱动级 / 增益 / 设计范围 / 钳位 / **实际可达** / 输出阻抗 / 极性。
**这张表就是固件测试计划与映射参数的直接输入**——把"上板试出来的"变成"表格里算出来的"，
直接减少软件测试工作量。

## 3. 更大的杠杆：原理图 → SPICE 网表导出

本次 `daout_clamp.cir` 是我**手工**从 `pinmap` 抄出来的（运放行为模型、TVS 反串联齐纳、电源轨、负载）。
工具可以做 `netlist --spice <页/网络>`：

- **运放**：行为模型（跨导 + 轨 + 限流）——模板已有，本项目可直接复用
- **TVS**：两只齐纳反串联，`BV` 直接取器件属性的"击穿电压"
- **磁珠/PTC/电阻电容**：L+DCR / R / C
- 电源轨由网络名（`+13.6V` 等）生成源

价值：把"读网表 → 搭仿真"从小时级压到分钟级，且评审阶段就能给出量化的"能到多少伏"。
**不建议自己做求解器**——导出网表交给 LTspice/ngspice 跑即可。

## 4. 反向能力：从端子需求反推前级要求

给定"我希望端子在 3~8 V 之间"，反算：

- DAC 需要输出的电压范围（→ 直接规定固件映射）
- 反馈电阻该怎么改（甚至给出最近的标准阻值对）
- 现有钳位件是否还挡路

这是把"**软件试错**"换成"**表格计算**"的最直接一条。

## 5. 实现建议（贴合既有路线图，不另起炉灶）

| 步骤 | 内容 | 依赖 |
| ---- | ---- | ---- |
| 前置 a | **器件属性结构化**：把 `components` 的原始属性串解析成字典并归一键名（`Vrwm/VBR/Vclamp/Isat/Ihold/DCR/阻值/容值/供电范围/GBW/RRO`）| 纯解析，最易做；BOM/选型也受益 |
| 前置 b | **驱动级识别**（保守版）：只在"运放 + 反馈电阻环绕"这一常见拓扑上给候选，人工确认入库（符合工具既有"分级置信度"原则）| 依赖 a |
| 前置 c | **参考电位识别**：同相端接的是参考源（本次 `+1.96V-REF`）还是地 | 依赖 a |
| R1~R4 | 四条 `check(ctx)` | 依赖 a(+b/c) |
| 报告 | 端子电气包络表（md/csv）并入 findings | 依赖 R1 |

**阈值建议**：`钳位余量 = VBR_min − 设计上限`，`< 0.5 V` 即 WARN，`< 0` 即 ERROR。

## 6. 不建议做的（避免过度设计）

- ❌ 通用 SPICE 求解器 / 全自动拓扑识别任何电路
- ✅ **先只覆盖"运放输出级 + 端子保护件"这一个高频形态**——本项目 6 个模拟输出级全是它
- ✅ 其余形态（比较器、基准、开关电源）后续按需增量

## 附：一个方法论上的提醒

本次排查里，**"工具给的属性串"是决定性证据**（`SMAJ5.0CA` 的 `击穿电压:7V` 直接锁死结论），
但它是**以人类可读的字符串**形式给出的。若要把这类判据变成规则，
第一件要做的事就是**把这些字符串变成可比较的量**——这也是 §5 前置 a 排在最前面的原因。
