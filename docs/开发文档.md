# 开发文档 — lceda_sch_reader

> 面向后续开发/排障的内部笔记。使用说明见 README，规则见 skill/SKILL.md，
> 变更历史见 docs/变更记录*.md 与各专项文档。**改动解析层前先读本文第 2、4 节。**

## 1. 架构

单文件 CLI（`lceda_reader.py`），**抽象接口层 + 内容特征路由** + 三后端：

| 后端 | FORMAT_NAME | 内容特征 |
| --- | --- | --- |
| `LcedaDB` | .eprj2（V2.2 SQLite） | SQLite magic + documents 表非空 |
| `EproDB` | .epro（V2 ZIP） | ZIP magic + project.json |
| `Epro2DB` | .epro2（V3 ZIP） | ZIP magic + *.epru / project2.json |

### 接口层（SchemaBackend ABC）

- 全部后端继承 `SchemaBackend`，10 个 @abstractmethod
  （schematics/schem_map/sheets/sheet_text/sheet_records/device_map/
  device_attrs/symbol_of_device/symbol_pins/datasheet_rows）——**缺实现
  在实例化时即报 TypeError**（历史上 EproDB 缺 sheet_text、datasheets
  直连 db.cur 各崩过一次，ABC 后此类漂移在开发期即被拦截）。
- 基类提供：`path`、`project_name()`（=文件名去扩展名）、`decompress`
  恒等实现、`cbb_symbol_board_map()` 默认 {}、四个缓存槽
  （_dmap_cache/_cbb_sym_map/_cbb_sig/_cbb_dom_cache）。
- 接口契约（详见类 docstring）：sheets() 返回全 docType 行由调用方过滤；
  sheet_records 返回统一 V2 数组模型；坐标统一 V2 语义（Y 向下），格式
  差异在后端内转换；取页一律 uuid。

### 路由（detect_backend）

**内容特征优先，扩展名仅参考**：ZIP magic(PK) → 按 project2.json/.epru/
project.json 分派；SQLite magic → documents 表非空=LcedaDB，**空+
project_structures=新版加密格式 → UnsupportedFormatError（明确报错并指引
导出 .epro/.epro2，此前会静默返回空结果的真实事故）**；其余 magic 报错
列出支持格式。新增格式三步：实现 SchemaBackend 子类 → detect_backend
登记特征 → 完成（命令层零改动）。

### 解析管线与调用方

```
parse_sheet(db,uuid)          # components/nets(stub)/attrs/no_connect/dnp
_collect_pinmap_data          # comp_pins(引脚绝对坐标)/wires/endp/pt_wires
resolve_nets_by_domain        # 并查集连通域 → dom{(des,pin):net}
  └ _expand_cbb               # CBB 展开（限深 2）
cmd_pinmap/pins/nets/netlist/netfind/find/trace/link-check/bom/...
```

## 2. 各格式关键事实与陷阱（改代码前必读）

### 2.1 .eprj2（V2 SQLite）

- uuid 双命名空间互斥：Symbol→components 表、Device→devices 表；桥接=
  attributes 表 key='Symbol'。实例 ATTR 的 Symbol/Device 值即对应 uuid。
- **dataStr 有两种形态**：`base64` 前缀 + base64(gzip(NDJSON))（用户工程），
  或**直接明文 NDJSON**（官方示例工程实测，如 示例工程_快速入门）——
  decompress 已兼容两者；新增编码形态在此扩展。
- 页标题块：**不要依赖 cid=="e1"**（现按"含 @ 属性组件"判定，e1 兜底）。
- 同名页：documents.display_title 非唯一，一切按 uuid 取页；
  `resolve_page` 未指定 --schematic 且重名时 stderr 告警取第一个。
- **PCB 文档（docType=3）**：`pcb_inventory()` 解析，记录布局与 SCH 不同——
  COMPONENT `["COMPONENT",cid,layer,?,x,y,rot,内联attrs]`；**跨文档映射键
  = COMPONENT 内联属性 "Unique ID"（ggeN 短ID），SCH/PCB 双侧同值，
  实测交集 100%（PCB 469/469 全命中 SCH 480）**；32 位 hex 是
  Device/Footprint uuid，不跨文档共享，勿混用。PCB ATTR 布局与 SCH 不同：
  `[type,id,?,parent,?,x,y,key,value,...]`（key/value 在 [7]/[8]，SCH 是
  [3]/[4]）。PAD_NET=[type,compCid,pinNum,net,padId] 即焊盘网络归属。
  工程可含多个 PCB 文档（历史快照/副本如 PCB1_1/PCB2/PCB3），`pcbsch`
  命令按匹配数取主板打印明细；空 PCB 文档（0 元件）如实输出。
  **三后端均已支持**：LcedaDB=documents.docType=3；EproDB=ZIP 内
  `PCB/<uuid>.epcb`（布局与 SQLite V2 完全一致，标题=project.json
  pcbs 的文件名）；Epro2DB=_docs docType=="PCB"（COMPONENT attrs 内联、
  ATTR parentId/key/value、NET 名在 head.id JSON 数组、PAD_NET 的 net 在
  body.padNet），sheet_records(doc_type=3) 统一转 V2 布局。
  实测跨格式 UID 稳定：涡流 epro2 备份 PCB2 与 SQLite PCB2 同为 125 元件
  全匹配零改名。
- **渲染（render 命令）关键事实**：字体与文字位置**工程里就有存储，勿发明排版**——
  - `FONTSTYLE [type,id,color,family,?,size,bold,italic,...]`（页文档与
    符号文档各有样式表；size 单位与坐标一致=0.01inch，常见 10~20；
    空值继承默认）。首版渲染器硬编码大字号导致"文字糊成一坨"，教训：
    先探针确认存储字段再写渲染。
  - 页实例 `ATTR len>=12`：`[7]/[8]`=显示坐标、`[9]`=旋转、`[10]`=样式
    引用、`[11]`=隐藏位——位号/值在 EDA 里摆好的位置直接可用。
  - `TEXT [type,id,x,y,rot,text,styleId,flags]`；`LINESTYLE` width 多为
    null→默认细线。
  - 符号图形原语：POLY(平铺数组+closed)/RECT/CIRCLE(cx,cy,r)/ARC(**三点
    弧**：起/弧上/终，采样折线规避 SVG sweep 歧义)/PIN(a[6]=长度,
    a[7]=旋转)。EproDB esym 有 HEAD.originX/Y 需先减。
  - 显示项可裁剪：render_config.json（工具目录自动加载）/--config/
    --no-labels/--no-texts/--pin-numbers——审查默认关引脚名号，
    大段设计注释可 --no-texts 避免遮挡。
- **新版分支加密格式**：documents/schematics 等主表为空，内容在
  `history_data`（base64+加密，熵 8.00 bits/byte）；工程树在
  `project_structures.structure`（明文 JSON，含 boards/sheets/blockSymbols）。
  判别方法：`SELECT COUNT(*) FROM documents` 为 0 即新版——detect_backend
  会抛 UnsupportedFormatError 明确报错（2026-08-21 前 曾静默返回空结果）。
- 0Ω 跳线判定必须走 `_is_zero_ohm(title, desc)`（精确 token，
  "10R/50R0/0710RL" 不误判）；短接符=symbolType 22。

### 2.2 .epro（V2 ZIP）

- WIRE segs 是**平铺点链** `[x1,y1,x2,y2,y3,...]`（相邻点成段），与 .eprj2
  的嵌套段不同——统一走 `_norm_segs()`，新消费点禁止自行解析 segs。
- COMPONENT a[2] 是符号 uuid 引用而非标题——EproDB.sheet_records 归一化为
  空串，parse_sheet 用 Name 属性兜底 title。
- 页标题为 `板名::页名` 复合式；CBB 模板板（_CBB_* 等）也在 boards 里。
- **CBB 精确链接 = `project.json.symbols[黑盒uuid].title == 模板板名`**
  （立创EDA 导入还原机制，实测确认）。Reuse Block/BatchReuse 实例属性为空，
  不要试图从实例属性找链接。
- EproDB.device_map 的 display 位优先 MPN 类属性（Supplier Part 仅兜底）。

### 2.3 .epro2（V3）

- epru 行格式 `{header}||{body}|`；DOCHEAD 开启文档，同 uuid 多段**按
  ticket 最终一致合并**（Epro2DB._index 按段顺序聚合）。文件可达 63MB/
  23 万行，首次索引约数秒。
- 层级链：BOARD ← SCH.meta.board ← SCH_PAGE.meta.schematic。
  **CBB 模板的 SCH 无 board 字段**——sheets() 按标题回退同名 BOARD。
- **坐标系 Y 向上**（V2 向下）：所有坐标输出前 `-y`；且须先减
  CANVAS.originX/Y 再翻转（符号 CANVAS origin 非 0，如 CBB 符号 (60,-80)）。
  页 CANVAS origin 通常 (0,0) 但代码已做通用处理。**新增坐标消费点必须
  走 sheet_records/symbol_pins 的合成结果，不得自行读原始行。**
- COMPONENT 无 title 字段：合成时 **title 位放 partId**（= 符号内 PART 名，
  如 "OPA2189ID.2"；普通器件 partId 即 PART 名，CBB 黑盒是 pid 占位符）。
  这比 Name 属性更完备（部分实例无 Name attr）。
- 实例 Symbol attr 值 = SYMBOL 文档 uuid（32hex 与 16hex **混杂**）；
  symbol_pins 兼容 uuid/标题（_sym_uuid_by_title 同 title 取最新 ticket）。
- **符号类型 = SYMBOL META.docType**：17=CBB / 18=电源 / 19=NetPort /
  22=Short / 25=OffPage（按 19 处理）/ 2=普通。V3 无 HEAD.symbolType。
- 引脚名/号 = ATTR 键 "Pin Name"/"Pin Number"/"Pin Type"（parentId=PIN id）。
- DEVICE META.attributes 内联全部属性（含 Datasheet/LCSC Part Name）。
  实例 Device uuid 可能不在 DEVICE 文档中（导出库不全）——device_map 用
  页上实例自带属性（Manufacturer Part 等）合成兜底条目。
- INSTANCE 文档（uuid 编码 `<sch>_$<母图页>~<实例cid>_$<模板页>` +
  INSTANCE_ATTR{Designator:...}）= **CBB 实例唯一精确映射 + 成员母图位号**
  （已实现 `Epro2DB.cbb_instances()`，_expand_cbb 匹配链第②级优先采用；
  INSTANCE_ATTR 仅记录被改过位号的成员，未记录的沿用模板位号）。
- **Device→Symbol 桥**：DEVICE META.attributes['Symbol'] = 符号文档 uuid
  （部分实例缺 Symbol 属性时唯一途径——MCU主控 U3/STM32 100 脚曾因此
  0 引脚，已修 symbol_of_device）。
- **NO_CONNECT 的 parentId 为 "实例cid-引脚id"（横杠复合）**，与 V2 的直接
  拼接不同——Epro2DB.sheet_records 合成 ATTR 时已归一化（去横杠），实测
  170/170 全部命中（2026-08-21 之前曾全部漏标）。
- NetPort/电源符号的端口名在实例 **Name 属性**（title 位是 partId）——
  _expand_cbb 的 port_titles 已按 Name 优先处理，改动时保持。
- 引脚无 Pin Name 时（电源符号/黑盒）回填 number 或 "1"，避免输出
  `PORTxxx.None` 观感问题。
- **epru 增量合并语义（易错点）**：ticket 在各段内独立计数，不能全局比较；
  同 (type,id) 记录以 **(段序, ticket) 双键**取最新。早期实现全局比 ticket
  导致误覆盖（265→139 网），未合并则历史轨迹叠加（新旧 LINE 全聚进同一
  WIRE → 连通域爆炸、单页 GND 成员 355）。改动合并逻辑务必双场景回归。
- **总线 BUS/busEntry（2026-09-03 实测，含总线样本后实现）**：
  V3 中 busEntry **嵌在 BUS 记录体内**（非独立行）；总线图形是
  lineGroup=BUS id 的 LINE；组名=BUS id 上的 NET 属性（D[0:7]）；
  入口 pointX/Y 是**分支侧**端点（导线自动修剪到距总线 busEntryLength=10
  处），order 供组名展开（expand_bus_net）。引擎生成的入口只在活模型，
  需用户动作事务才落盘。Epro2DB 已发射合成 BUSENTRY 行，parse_sheet 做
  无名分支推断命名 + sheet["buses"] 组信息；**总线是编组不是电气连接，
  勿做域合并**。详见 docs/总线BUS-BUSENTRY格式与实现-2026-09-03.md。
- **port_nets 补充的合成点**会进入 sheet["nets"] 但不在 WIRE 构建的
  parent 中——resolve 已做端点拓扑闭合（endp_all 全量 setdefault），
  否则悬空端口引脚命中合成点即 KeyError（导出包实测）。

## 3. CBB 展开（_expand_cbb）

匹配优先级：`--cbb-map 位号=板名/页名` > `db.cbb_symbol_board_map()`
（Epro2DB 原生 docType=17；EproDB symbols.title）> 同目录 *.eprj2 的
structure.blockSymbols > **端口名集合匹配**（最后兜底：候选按内容指纹
分组——指纹=(位号,title,器件型号) 语义身份非 uuid，使 `_old` 副本归等价；
唯一组采纳取字典序最小，多组歧义 stderr 告警跳过）。

展开语义：模板内部连通域按"端口名"映射进实例引脚父网络，生成
`实例位号.模板位号` 条目（如 `CBB6.U13`），net="内部网络,父网络"逗号并集，
借同名归并贯通。模板内桥接多端口的域会把多个父网络经展开条目连通。

边界/假设（排查展开问题先看这里）：
1. 实例引脚父网络为空（接未命名线）时不产生该端口的别名条目；
2. port_net 缺失时回退假设"端口名=内部网络名"（LCEDA 官方约定）；
3. 限深 2（嵌套 CBB）；PORT*/SHORT* 不作为展开条目；
4. pinmap 保持黑盒视图、find 不索引展开位号——**是有意设计非遗漏**；
5. conn_nets 排除 PORT*/SHORT* 合成位号（否则 link-check 灌数万假候选，
   曾实测 70070→183 的回归教训）。

0. **全盘格式验证（2026-08-21，probes/verify_all_formats.py）**：本机 15 个
   工程文件全部 PASS。过程中发现并修复：① V3 Device→Symbol 桥缺失

   修复后 epro 与 epro2 均 265 网）。注意：涡流传感器-V1.0.eprj2（1573
   元件/101 网）是**另一设计版本**（含双版同名图纸），与 epro2 备份
   （736/79，对应涡流传感器.eprj2）内容不同，对比时勿混用。
1. ~~V3 NO_CONNECT~~ **已闭环**（横杠复合归一化，170/170）。
2. **V3 短接符覆盖面**：docType=22 已支持；Piezo .epro2 实测 SHORT 合成
   位号正常参与连通域。跨格式行为差异未全面比对。
3. **OffPage(25)→19 是推断**：样例工程 0 实例无法实测；已按 NetPort 语义
   处理并保留，若未来工程使用需实测。
4. DEVICE/SYMBOL uuid 32/16hex 混杂：device_map 直接交集不全，其余靠
   实例属性合成兜底——若实例属性也不全则型号列为空。
5. **dom 网络分隔符**：内部 NET_SEP(\u241f) 规避网络名含逗号的歧义；
   json `pinmap.pins[].net` 为逗号显示兼容字段，精确列表见新增的
   `nets` 数组字段；历史逗号拼接值 net_tokens 双向兼容。
6. trace --no-power 的 `is_power_net` 为启发式（GND 子串/电源族前缀/数值
   电压式），锚定全名；特殊命名电源（如 `+5V_SB`）不会被跳过——只影响
   trace 展开范围不影响正确性。
7. 性能：Epro2DB 首次索引全量扫描 epru（数秒级）；_cbb_sig 首次构建遍历
   全部页；trace 全网索引 O(页×网络)。大工程（>100MB epru）未测。
8. 多工程命令（netfind/trace/link-check/find/search）在 .epro/.epro2 上
   未系统验证（理论上后端无关）。
9. find_eprj 自动探测优先级 .eprj2 > .epro2 > .epro；同目录多命中会报错
   要求显式 --eprj（防止静默选错）。
10. CBB 展开条目为混合位号：INSTANCE_ATTR 记录过的成员用母图位号，未
    记录的沿用模板位号（与立创EDA 行为一致——它也只记录改名的成员）。

## 5. 调试指南

探针脚本统一放 `probes/`（**禁止放系统临时目录**，AGENTS.md 测试规则第 7 条）。
关键脚本：

| 脚本 | 用途 |
| --- | --- |
| `smoke2.py` | LcedaDB 回归（9 命令 + json 校验），改解析层后必跑 |
| `audit_probe*.py` | 设计审查探针（0Ω/旋转/NetFlag/BOM 归并/容差插桩） |
| `verify_fix.py / verify_bom.py / verify_dnp.py` | 修复后定向验证 |
| `epro_probe.py / epro_fmt.py` | .epro 冒烟 + DNP 标志分布 |
| `epro_cbb_link.py` | .epro CBB 链接证据（symbols.title） |
| `cbb_link*.py / review_probe.py` | CBB 实例属性/符号映射/覆盖率调查 |
| `eprj_blocksym*.py / eprj_hist*.py` | 新版 .eprj2 structure/blockSymbols/加密取证 |
| `epro2_probe4~8.py` | V3 格式侦察（docType 分布/页结构/符号类型/CBB） |
| `dbg_epro2_dom.py / dbg_epro2_part.py` | epro2 网络解析/PART 匹配调试 |

排障路径速查：
- 引脚全"(未命名)" → 几何断链：查 sheet["nets"] 命名占比 → 引脚绝对坐标
  vs wire 端点距离（dbg_epro2_geo.py 模式）；
- CBB 展开 0 条 → 按 匹配链逐级打印：insts → cbb_symbol_board_map →
  _resolve_cbb_target → t_dom → port_net → pin_parent（dbg_expand2.py）；
- json 输出 INVALID → 检查是否有 print 打到 stdout（banner 类一律 stderr）；
- BOM 型号/描述错 → 确认走 device_uuid 键（symbol_uuid 兜底会错并多器件
  符号），见设计审查文档 A5。

## 7. 教训与原则

- **EDA 应该有的功能它就应该有——努力寻找而不是拒绝**（2026-08-23，
  PCB↔SCH 映射调查）。调查"原理图与 PCB 如何关联"时，第一版探测只比对了
  ATTR 里的 Unique ID（32hex）得出交集为 0 的假象，一度倾向"PCB 不带
  SCH 信息"。实际上立创EDA 在 COMPONENT **内联属性**里放了 `Unique ID`
  （ggeN），SCH/PCB 双侧同值、全局唯一——这是 EDA 软件设计上必须存在的
  关联机制（否则无法同步更新）。**教训：判断某数据"不存在"之前，先从
  软件的功能原理推演它必须在哪，穷尽记录类型（内联 dict / 各位置 ATTR /
  独立表）再下结论；字段布局与 SCH 不同（如 PCB ATTR key/value 在
  [7]/[8]）时，按 SCH 布局读出的垃圾值会造成系统性误判。**
- 探测脚本先在单文档小样本上人工核对原始记录布局（dbg_pcb_raw.py 模式：
  直接 dump 前几条记录逐字段看），再写全量统计逻辑；否则解析 bug 会以
  "合理-looking 的错误数字"形式污染结论。
