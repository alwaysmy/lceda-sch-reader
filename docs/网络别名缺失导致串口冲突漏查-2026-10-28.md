# 网络别名缺失导致串口冲突漏查

- 日期：2026-10-28
- 类型：缺陷分析 + 改进建议
- 涉及命令：`netfind` / `nets` / `pinmap` / `search`
- 涉及代码：`lceda_reader.py` 的 `resolve_nets_by_domain` 与端口命名段（约 3704–3770 行）

---

## 1. 现象

排查 MMC-110 自研板的调试串口（USART2_TX = PD5）为什么发不出数据时，
用工具得出的结论是错的：

| 命令 | 结果 |
|---|---|
| `netfind USART2_TX` | 返回 6 个连接点：`U300.PD5`、`HDR300.2`、短接符两脚、两个端口符号 |
| 推论 | "这条线上只有 MCU 和排针" —— **错误** |

实际情况：`USART2_TX` 与另一个网络 **`ID_OUT`** 在电气上**是同一条网络**，
而 `ID_OUT` 上还挂着 9 个连接点，其中包含 `D600.C`（1N4148 阴极）——
`D600` 的阳极接 `U607.5Y`（74HC14 输出）。于是 **USART2_TX（MCU 强输出）**
与 **74HC14 输出**在同一条线上对顶，调试串口无法工作。

而 `netfind ID_OUT` 返回 9 个点（含 `D600.C`），`netfind USART2_TX` 返回 6 个点
—— **两个本该是同一网络的查询返回了互不包含的结果**。

---

## 2. 问题性质判定

按"工具信息不足 / 无功能 / 有功能但覆盖不全+提示不足"三类核对，结论是
**第三类为主，兼有第二类的成分**：

| 分类 | 判定 | 依据 |
|---|---|---|
| 工具提供的信息不足以判断 | **否** | 原始信息是齐的：`search USART2_TX` 能查到 `["ATTR","3e4c9acf2714ab95","24b149d719e92ccb","Name","USART2_TX"]`；`nets 内部通信总线` 也能看到该 `PORT24b149d719e92ccb` 出现在 `ID_OUT` 网络里。数据没缺。 |
| 完全没有对应功能 | **部分** | "端口命名"功能**存在**（见 §3），但**只覆盖"导线未命名"的场景**；"同一连通域多名字（别名）"没有对应实现。 |
| 功能存在但覆盖不全 / 提示不足 | **是（主要）** | 端口名在导线已有 `NET` 属性时被丢弃；输出里不显示别名关系；`search` 不给"该属性所在网络"的成员。 |

---

## 3. 源码定位

### 3.1 端口命名功能确实存在（约 3715–3745 行）

```python
for cid in port_cids:
    nm = net_of.get(cid) or attrs_of.get(cid,).get("Name")   # ← 3716
    if nm:
        port_nets[cid] = nm
if port_nets:
    for (des, cid), plist in comp_pins.items():
        nm = port_nets.get(cid)
        if not nm:
            continue
        for p in plist:
            if p.get("no_connect"):
                continue
            pt = (round(p["x"], 1), round(p["y"], 1))
            for wid2 in pt_wires.get(pt, ()):
                if net_of.get(wid2):        # ← 3733：导线已有名字就跳过
                    continue
                net_of[wid2] = nm
                ...
```

**两处问题**：

1. **3716 行**：`net_of.get(cid) or attrs["Name"]` —— 逻辑"或"。导线端点已有
   NET 名时，`Name` 属性**永远取不到**。本例中 `PORT24b149d719e92ccb` 的
   `Name = USART2_TX`，但它所在导线已有 `NET = ID_OUT`，于是 `nm = "ID_OUT"`，
   `USART2_TX` **被丢弃**。
2. **3733 行**：传播时 `if net_of.get(wid2): continue` —— 即使走到这里，也只给
   **未命名**导线补名字。导线有名字时不追加别名。

### 3.2 架构上其实支持"一个网络多个名字"

```python
# 约 363 行
def net_tokens(v):
    """dom 网络字段 -> 网络名列表（兼容 NET_SEP 与历史逗号拼接）。"""
    if NET_SEP in v:
        return [t for t in v.split(NET_SEP) if t]
    return [t for t in v.split(",") if t]
```

`_netfind_one` 判定命中时用的正是：

```python
if net and target in [t.upper() for t in net_tokens(net)]:
```

也就是说：**只要把 `ID_OUT` 与 `USART2_TX` 以多值形式（`ID_OUT⌟USART2_TX`）
写进 `net` 字段，`netfind USART2_TX` 立刻就能返回完整的 9 个点，且不需要改
任何下游逻辑。** 缺的只是"把端口名并入已有网络名"这一步。

### 3.3 注释与实现不一致（容易误导使用者）

约 3708–3712 行注释写：

```
# 端口名有两个存放位：`Global Net Name`（网络标识/电源符号）与 `Name`
# （网络端口符号，Symbol uuid 实测 ...）。
# 后者同样必须认——否则其 stub 线无 NET 时端口名整条丢失，网络退回
# 立创自动名（实测本工程 I2C2_SDA/I2C2_SCL/... 退化成 PA8/PA9/...）
```

注释本身准确（描述的是"stub 线**无 NET** 时"的场景），但读起来容易被理解成
"`Name` 存放位已完整支持"。**建议在注释里明确写出当前限制**：
"仅当导线无 NET 属性时端口名才生效；导线已有 NET 时端口名目前被丢弃"。

## 4. 改进建议

### P0-1 端口名并入已有网络名（别名合并）

```python
# 3716 附近，改为收集两个候选
net_nm   = net_of.get(cid)
attr_nm  = attrs_of.get(cid,).get("Name")
if net_nm and attr_nm and net_nm != attr_nm:
    port_nets[cid] = f"{net_nm}{NET_SEP}{attr_nm}"   # 多值
else:
    port_nets[cid] = net_nm or attr_nm
```

并在 3733 处对**已命名**导线也追加别名（把该导线所属连通域的名字改成多值），
而不是简单 `continue`。注意去重与幂等（同一网络可能被多个端口命名）。

### P0-2 输出标注别名关系

`nets` / `pinmap` / `netfind` 输出里显式标注，例如：

```
ID_OUT    ← H401, PORT24b..., D502, R4 ...
            别名: USART2_TX
```

`--json` 里增加 `aliases` 字段。这样使用者一眼能看出"两个网络名是同一根线"，
不必自己比对 ATTR。

### P1-1 `search` 命中 `Name` 时补充所在网络

当前 `search USART2_TX` 只回到 ATTR 原始行。若命中项是端口符号的 `Name`，
应附带："该符号所在网络 = ID_OUT，共 9 个成员（列表）"。这次如果输出里有这
一句，问题当场就能定位。

### P1-2 增加"网络别名/单端多驱动"检查命令

- `netfind --check-drive` 或独立的 `conflict <网络名>`：列出网络上每个节点，
  按器件型号推断驱动方向（74HC14：A=输入/Y=输出；1N4148：A→C 单向），
  标出"≥2 个输出"的组合。
- 至少先做无型号推断的版本：输出"该网络上所有引脚 + 器件型号"，让人判断。

### P2 使用侧注意事项（非工具缺陷）

排查通信线时，应对**同一引脚的所有网络名**都查一遍（引脚号、网络名、以及任何
端口符号的名字），并逐个确认节点是驱动还是被驱动。本次只查了 `PD5`/`USART2_TX`
就收尾，是漏查的直接原因。
